# 项目库 AI 协作生成机制 V0

项目：数学小讲师联盟  
阶段：阶段3补充交付｜项目库与 AI 协作  
版本：V0  
状态：作为后续“AI生成项目草案、项目模板库、管理员审核发布”的产品与工程依据

---

## 一、结论

项目库与 AI 的协作不建议一开始做成“前台一键生成并立即发布”。

推荐采用两阶段：

### MVP 阶段：AI辅助生成，人工导入/后台草稿审核

```text
犟爸/老师与AI商讨项目内容
→ 形成结构化项目文档或JSON
→ 管理员导入项目草稿库
→ 老师/管理员编辑审核
→ 管理员发布到项目库
→ 项目营展示或推荐
```

### P1 阶段：网站后台一键生成项目草稿

```text
管理员/老师在后台输入生成条件
→ AI生成项目草案
→ 自动写入 ProjectDraft
→ 老师编辑
→ 管理员审核
→ 发布到项目库
```

不建议：

```text
AI一键生成 → 自动公开到项目营
```

原因：项目服务对象是小学低年级孩子，项目必须经过教育适配、安全、材料、家长介入度、数学准确性、协作可行性、付费边界等检查。

---

## 二、AI生成项目的底层逻辑

AI不是“编一个活动”，而是按固定教育设计框架生成项目。

每个项目必须回答 12 个问题：

1. 这个项目服务哪个年级段？
2. 对应哪些数学知识点？
3. 孩子会经历什么真实情境？
4. 孩子需要观察、测量、画图、表达、合作中的哪些行为？
5. 项目成果是什么？
6. 所需材料是否安全、低成本、家里容易获得？
7. 是否需要家长协助？协助到什么程度？
8. 是否适合 3 人小组异步协作？
9. 老师需要审核什么？
10. 免费项目和付费项目的服务边界是什么？
11. 如何避免变成刷题或成人化报告？
12. 如何记录到成长护照和能力观察？

## 三、项目产出水准标准

AI生成项目必须达到以下标准，才允许进入项目库候选。

### 3.1 教育标准

- 面向小学1–3年级，语言儿童可理解；
- 数学知识点准确；
- 不依赖超纲概念；
- 不把项目做成变相刷题；
- 有真实观察、操作、表达或合作；
- 有低龄孩子能完成的成果形式；
- 允许家长辅助操作，但不让家长替孩子完成思考。

### 3.2 项目结构标准

每个项目必须包含：

1. 项目名称；
2. 一句话介绍；
3. 适合年级；
4. 核心知识点；
5. 能力观察方向；
6. 所需人数；
7. 建议周期；
8. 所需材料；
9. 任务卡 3–5 步；
10. 小组协作方式；
11. 成果提交形式；
12. 老师审核要点；
13. 分享范围建议；
14. 结营证书能力词；
15. 风险提醒；
16. 免费/付费适配建议。

### 3.3 儿童体验标准

项目应该让孩子感到：

- 我能开始；
- 我知道第一步做什么；
- 我可以用图、照片、语音、视频表达；
- 我不是在完成成人报告；
- 我能看到伙伴的想法；
- 完成后有一个真实作品。

### 3.4 家长信任标准

家长应该看得懂：

- 这个项目练什么数学；
- 需要准备什么；
- 大约花多久；
- 是否需要陪伴；
- 安全风险在哪里；
- 免费和付费区别在哪里；
- 退出/延期规则是什么。

## 四、项目草稿数据结构

建议新增 `ProjectDraft`：

```prisma
model ProjectDraft {
  id              String   @id @default(cuid())
  title           String
  shortIntro      String
  gradeRange      String
  knowledgeTags   String[]
  abilityTags     String[]
  requiredMembers Int      @default(3)
  suggestedDays   Int?
  materials       String[]
  taskCards       Json
  collaboration   String
  submissionTypes String[]
  reviewChecklist String[]
  certificateTags String[]
  riskNotes       String[]
  serviceType     ProjectType
  aiPrompt        String?
  aiModel         String?
  aiVersion       String?
  status          ProjectDraftStatus @default(AI_DRAFT)
  createdById     String?
  reviewedById    String?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}

enum ProjectDraftStatus {
  AI_DRAFT
  TEACHER_EDITING
  ADMIN_REVIEW
  NEED_REVISION
  PUBLISHED
  ARCHIVED
}
```

## 五、AI生成项目提示词框架

后台生成项目时，AI必须遵循固定框架：

```text
你是小学1–3年级数学项目制学习设计师。
请围绕{年级}、{知识点}、{生活情境}，设计一个适合3人异步协作的数学小项目。

必须遵守：
1. 不做刷题；
2. 不替孩子思考；
3. 任务可在家庭环境完成；
4. 材料安全、低成本、容易获得；
5. 孩子可以用照片、画图、语音、短视频表达；
6. 老师只做审核和必要引导；
7. 输出要适合“数学小讲师联盟”的低焦虑、真实思考、项目制学习气质。

请输出：
- 项目名称；
- 一句话介绍；
- 适合年级；
- 核心知识点；
- 能力观察方向；
- 所需人数；
- 所需材料；
- 任务卡3–5步；
- 小组协作方式；
- 成果提交形式；
- 老师审核要点；
- 结营证书能力词；
- 风险提醒；
- 免费/付费适配建议。
```

## 六、项目质量评分机制

AI生成后，系统或老师可按 100 分进行内部评分，不公开给孩子。

| 维度 | 分值 | 说明 |
|---|---:|---|
| 数学准确性 | 20 | 知识点准确、不超纲、不误导 |
| 儿童可完成性 | 20 | 一二三年级孩子能理解和开始 |
| 真实情境 | 15 | 来自生活观察、测量、图形、规律等真实经验 |
| 表达与合作 | 15 | 有讲述、画图、记录、讨论、协作 |
| 材料与安全 | 10 | 材料易得、安全、低成本 |
| 成果可展示 | 10 | 成果能进入成长护照或成果广场 |
| 运营可落地 | 10 | 老师审核成本合理，适合免费/付费边界 |

建议：

- 85分以上：可进入管理员审核发布；
- 70–84分：需要老师编辑后再审；
- 70分以下：不进入项目库。

## 七、MVP 与 P1 的边界

### MVP 做法

- 不在前台给用户开放“一键生成项目”；
- 由犟爸/老师与 AI 商讨项目内容；
- 形成结构化 Markdown / JSON；
- 管理员导入项目草稿；
- 老师和管理员审核；
- 发布到项目库。

### P1 做法

- 管理员后台增加“AI生成项目草稿”按钮；
- 输入年级、知识点、生活情境、项目类型、付费/免费；
- AI生成项目草案；
- 自动写入 ProjectDraft；
- 老师编辑；
- 管理员发布。

### 不做

- 不让学习者前台随机生成项目；
- 不让 AI 自动公开项目；
- 不让 AI 自动决定付费价格或退费规则；
- 不让 AI 替孩子完成项目成果。

## 八、项目发布权限

| 动作 | 老师 | 管理员 |
|---|---|---|
| 生成项目草稿 | ✅ | ✅ |
| 编辑自己负责项目 | ✅ | ✅ |
| 提交发布申请 | ✅ | ✅ |
| 最终发布到项目营 | ❌ / 可授权 | ✅ |
| 首页推荐 | ❌ | ✅ |
| 下架项目 | 可申请/负责项目可下架草稿 | ✅ |
| 删除有参与记录项目 | ❌ | ❌，只能归档 |
| 导出项目数据 | 默认❌ | ✅ |

## 九、示例项目结构

```json
{
  "title": "我家的小小测量师",
  "shortIntro": "用尺子和眼睛，发现家里物品的长度秘密。",
  "gradeRange": "一年级下–二年级上",
  "knowledgeTags": ["长度", "测量", "比较"],
  "abilityTags": ["观察", "记录", "表达", "合作"],
  "requiredMembers": 3,
  "suggestedDays": 14,
  "materials": ["尺子", "纸", "笔", "3个可测量的小物品"],
  "taskCards": [
    "选3个家里的物品，先猜一猜哪个最长。",
    "用尺子测量并记录。",
    "画一张简单比较图。",
    "和小组伙伴交流：你们测量结果有什么相同和不同？",
    "提交一张照片或短视频，说明你的发现。"
  ],
  "submissionTypes": ["照片", "短视频", "语音+图片"],
  "reviewChecklist": ["测量方法基本正确", "记录清楚", "能说出一个发现", "无隐私风险"],
  "certificateTags": ["观察记录", "测量比较", "讲清发现"],
  "riskNotes": ["不要拍到家庭隐私", "测量时注意安全，不爬高"],
  "serviceType": "FREE_BASIC"
}
```

## 十、验收清单

- [ ] AI生成项目必须先进入草稿；
- [ ] 草稿必须可人工编辑；
- [ ] 项目发布必须经过管理员确认；
- [ ] 每个项目必须包含任务卡、材料、安全提醒、成果形式；
- [ ] 每个项目必须标注年级、知识点、能力观察方向；
- [ ] 每个项目必须符合低年级儿童可完成性；
- [ ] 不允许 AI 自动公开项目；
- [ ] 不允许 AI 替孩子生成项目成果；
- [ ] 项目库支持归档，不硬删除有参与记录项目。
