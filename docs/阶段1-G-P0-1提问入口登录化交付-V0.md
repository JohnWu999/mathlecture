## 1. 本轮目标

阶段1-G的原则是：

> 公开内容可以浏览；真实互动必须登录注册。

P0-1聚焦提问入口：

```text
/qa/ask
```

目标：

1. 未登录用户不能直接看到完整提问表单；
2. 未登录用户先看到“登录后提问”的说明卡片；
3. 文案说明为什么需要登录：老师讲解完成后才能把视频和反馈推送给提问者；
4. 登录 / 注册入口保留回跳 `/qa/ask`；
5. 后端 `POST /api/questions` 继续保持 401 匿名写入保护；
6. “匿名提问”文案改为“匿名展示”，避免误解成无需注册即可提问。

### 2.2 `tests/stage1g-auth-boundary-rules.test.mjs`

3. 未登录态必须出现“登录后提问”；
4. 未登录态必须解释老师讲解完成后可把反馈推送给提问者；

6. 匿名文案不得再使用“匿名提问（保护提问安全感）”；

8. `POST /api/questions` 必须检查 session、未登录 401、创建问题时使用 `authorId: session.user.id`。

## 7. 服务器访问恢复说明

前两次部署尝试失败的直接原因是：误用了当前 `.ssh/` 下的几个非本项目生产服务器授权 key，因此均返回：

```text
Permission denied (publickey,password)
```

经回查历史会话和流程控制台，确认以前一直能访问服务器，是因为使用了项目早期交接记录中的专用部署 key：

```text
[REDACTED_KEY_PATH]
```

对应用户：

```text
ubuntu@159.75.144.28
```

恢复后验证：

```text
connected:VM-0-6-ubuntu:ubuntu
```

结论：

```text
访问受限根因不是服务器授权整体失效，而是本轮排查时遗漏/误用历史专用部署 key。
```
