## 一、低保真线框图目标

本文件不是最终视觉稿，而是把已确认的产品结构转成可设计、可开发、可验收的页面骨架。

低保真线框图重点解决：

1. 页面上应该有哪些区块；
2. 区块之间的优先级和阅读顺序；
3. 手机、平板、电脑如何自适应；
4. 关键操作按钮放在哪里；
5. 弹窗、表单、卡片、后台列表如何组织；
6. 哪些模块属于 MVP 必做，哪些可以后置。

## 二、全站布局原则 V0

### 2.1 响应式基础规则

| 设备 | 导航形式 | 内容布局 | 主要使用场景 |
|---|---|---|---|
| 手机 | Logo + 折叠菜单 | 单列卡片流 | 家长快速浏览、拍照上传、查看通知、分享海报 |
| 平板 | 顶部完整导航或较宽折叠菜单 | 2列为主 | 孩子阅读任务、查看项目、上传成果 |
| 电脑 | 顶部完整导航 | 2–3列、后台表格 | 老师审核、管理员管理、较完整协作空间 |

### 2.2 全站固定导航

前台主导航保持 5 个入口：

```text
首页 | 你问我答 | 项目营 | 成果广场 | 个人中心
```

不把登录/注册作为主导航页面。未登录用户点击受保护操作时，弹出登录/注册弹窗，登录后回到被打断流程。

### 2.3 正向成长展示原则

- 不做公开排行榜；
- 不公开积分总数；
- 不出现“最高赞”“最火”“超过多少人”等刺激性表达；
- 公开展示以身份点亮、作品、项目成果、温暖数据为主；
- 成长细节、积分、能力观察记录放在个人中心或后台。

### 2.4 统一卡片原则

MVP 优先统一 4 类卡片：

1. 问题卡片；
2. 讲解视频卡片；
3. 项目卡片；
4. 成果卡片。

这样后续前端组件可以复用，开发速度更快。

### 4.3 提交问题页/弹窗线框图

低年级孩子不承担“概括标题”和“判断知识点”的主要压力。页面应该让家长辅助确认，而不是让孩子像成人一样填复杂表单。

```text
┌──────────────────────────────────────────────┐
│ 提出一个真实问题                              │
│ 把你正在想不明白的题目拍清楚，我们一起等待小讲师。│
├──────────────────────────────────────────────┤
│ 1. 上传原题                                  │
│ ┌──────────────────────────────────────────┐ │
│ │  拍照 / 上传图片区域                      │ │
│ │  提示：请尽量拍清楚完整题目                │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ 2. 题目文字版                                │
│ ┌──────────────────────────────────────────┐ │
│ │ 系统识别/家长补充的题目文字                │ │
│ │ 家长可修改确认                            │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ 3. 问题标题                                  │
│ 灰色说明：给这道题起一个方便别人看懂的名字，   │
│ 不是写解题过程；系统会先生成，家长只需确认或微调。│
│ ┌──────────────────────────────────────────┐ │
│ │ 建议标题：这道面积题我不知道先算什么        │ │
│ │ 可编辑                                    │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ 4. 年级                                      │
│ [一年级▼]                                    │
│                                              │
```

### 6.3 协作空间消息提醒规则

- 老师留言、小组成员@我、任务状态变化、审核退回/通过，均形成站内消息。
- 导航栏“个人中心”上方显示红点或数字气泡；进入个人中心后分为“我的消息 / 项目提醒 / 审核通知”。
- 对低年级孩子，提醒文案要短：如“老师给你的小组留言了”“你的小组有新照片”。
- MVP先做站内红点 + 个人中心消息列表；微信/短信等外部提醒后置，避免过早增加隐私和运营复杂度。

### 6.4 协作空间 MVP 边界

MVP 做：

- 任务卡；
- 小组留言流；
- 图片/视频/语音+图片/文字上传；
- 老师提醒；
- 系统状态提醒；
- 最终成果提交；
- 分享范围选择；
- 后台留痕。

MVP 不做：

- 实时在线协作文档；
- 视频会议；
- AI贡献分析；
- 复杂群聊。

## 十四、V2客观复核后的修订清单

1. 首页首屏卖点标签从“思维开窍”进一步调整为“真实思考”，避免过度承诺，更贴近孩子在提问、讲题和项目中的真实学习过程。
2. “适合谁/暂不优先适合谁”均精简为3条客观条件，降低判断负担，避免理想化或负面化用户画像。
3. 你问我答电脑端与手机端统一使用“推荐讲解”；题目详情页或单题下方才使用“已发布讲解”。
4. 项目卡片将“满3人自动解锁”改为“满3人自动开组并开启协作空间”，区分个人参与资格与小组开组状态。
5. 项目卡片弱化公开积分表达，将“20积分”改为“完成基础项目/达到基础参与条件”，积分继续作为私密成长账本和后台判断依据。
6. 付费项目报名改为“可选联系方式 + 企业微信二维码 + 后台跟进状态”，既保护家长敏感度，也避免报名链路断点。
7. 视频/成果封面明确为“站内展示图片”，MVP不要求家长或老师把封面剪进视频首帧；自动合成进视频后置。
8. 成果广场“统一封面”改为“类型化封面”，讲题视频封面与项目成果封面分开。
9. “我的影响力”去增长化，不强调邀请注册人数，改为“我的分享启发了X位同学开始一次数学探索”。
10. 项目详情页“适合谁”改为更客观的基础条件，不预设孩子一开始就会合作或表达。
