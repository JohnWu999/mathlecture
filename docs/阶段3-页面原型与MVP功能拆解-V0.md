1. 每个核心页面的**原型结构**；
2. 每个关键动作的**状态流转**；
3. MVP 必须实现的**功能清单**；
4. 可以后置的**增强功能**；

阶段3完成后，可以进入：

- 后端接口拆分；
- MVP 迭代排期。

## 二、MVP 产品边界

### 2.1 MVP 必须跑通的三个闭环

#### 闭环一：孩子提问 → 审核 → 展示 → 等待小讲师

最小路径：

1. 学习者登录；
2. 点击“我要提问”；
3. 提交题目文字/图片、年级、知识点、困惑描述；
4. 系统显示温暖提示；
5. 老师后台审核；
6. 审核通过后进入你问我答列表；
7. 其他孩子可以查看并认领。

#### 闭环二：小讲师认领 → 上传讲解 → 审核 → 发布

最小路径：

1. 学习者点击“我要当小讲师”；
2. 进入可认领问题列表；
3. 选择题目；
4. 弹出认领贴士；
5. 确认后锁定题目，开始 48 小时倒计时；
6. 上传讲解视频；
7. 勾选是否愿意公开分享；
8. 系统显示温暖提示；
9. 老师审核；
10. 审核通过后公开到成果广场或仅进入个人成长记录。

#### 闭环三：项目营报名/解锁 → 协作空间 → 成果提交 → 审核/记录

最小路径：

1. 学习者进入项目营；
2. 查看项目卡片；
3. 根据免费/已解锁状态报名；
4. 弹出项目认领贴士；
5. 进入项目任务书和协作空间；
6. 小组留言、任务卡、过程上传；
7. 提交项目成果；
8. 勾选是否愿意公开分享；
9. 老师审核；
10. 成果进入成果广场和成长护照。

## 三、页面原型结构 V0

### 3.1 首页原型

#### 页面结构

```text
[顶部导航]
Logo 数学小讲师联盟 | 首页 | 你问我答 | 项目营 | 成果广场 | 个人中心

[首屏 Hero]
标题：数学小讲师联盟
Slogan：会思考，爱数学
副标题：小学低年级孩子的数学小讲师共学社区
标签：小学1-2年级 / 同伴互助 / 项目制学习 / 低焦虑成长
按钮：我要提问 | 看看孩子怎么学

[平台温暖数据]
已提出 X 个好问题 / 已解答 X 个问题 / X 位孩子参与探索 / X 个小组完成协作

[孩子怎么学]
卡片1 提出真实问题
卡片2 认领一道我能讲的问题
卡片3 参加一个数学小项目
卡片4 留下自己的成长作品

[适合谁 / 不太适合谁]
双栏卡片

[你问我答预览]
3个问题卡片 + 1-2个讲解预览
按钮：我要提问 / 去认领一道题 / 进入你问我答

[项目营预览]
免费基础项目卡 + 进阶项目样例

[精选成果预览]

[安全、审核与低焦虑承诺]
发布前审核 / 不做公开排名 / 孩子是真正主角
```

#### MVP 功能要求

- “我要提问”未登录时弹登录/注册弹窗，登录后返回提交问题流程；
- “看看孩子怎么学”锚点跳转到首页内部模块；
- 平台数据可先使用真实统计 + 缓存，早期数据不足时可隐藏或展示“正在一起成长中”；
- 不出现排行榜、公开积分、公开排名。

- 我知道了，开始认领；
- 我再想想。

### 3.4 项目协作空间原型

#### 页面结构

```text
[项目标题区]
项目名 / 当前阶段 / 截止时间 / 小组成员

[老师公告区]
项目目标 / 本周任务 / 注意事项

[任务卡片区]
任务1：观察/测量
任务2：画图/记录
任务3：讨论/讲解
任务4：整理/上传
状态：未开始 / 进行中 / 已完成

[小组留言区]
文字留言 / 图片上传 / 系统提醒 / 老师提醒

[作品上传区]
上传草稿 / 图片 / 视频 / 文档

[项目进度区]
已加入 → 已分工 → 已提交草稿 → 已完成作品 → 老师已点评 → 已结营

[成果提交区]
提交最终成果
勾选：我愿意公开分享到成果广场
```

#### MVP 边界

MVP 做：

- 留言；
- 任务卡；
- 上传；
- 进度状态；
- 老师公告；
- 成果提交；
- 后台留痕。

MVP 不做：

- 实时在线协作文档；
- AI 自动贡献分析；
- 复杂群聊功能；
- 视频会议。

## 四、核心状态流转

### 4.1 问题状态

```text
草稿 → 已提交 → 待审核 → 已通过/已退回 → 待认领 → 已认领 → 已讲解 → 已关闭
```

### 4.2 讲解状态

```text
已认领 → 待上传 → 已上传 → 待审核 → 已发布/已退回 → 成长记录已更新
```

补充规则：

- 认领后 48 小时未上传：自动释放题目；
- 无故放弃累计 3 次：暂停一段时间的认领资格；
- 讲解发布前必须审核；
- 公开展示需要授权。

### 4.3 项目参与状态

```text
可报名 → 已报名 → 已组队 → 进行中 → 已提交成果 → 待审核 → 已结营/需修改/已退出
```

补充规则：

- 免费项目无故退出累计 3 次：暂停免费体验资格；
- 付费项目按照项目营规则处理；
- 项目过程记录进入后台存档；
- 项目成果公开需要授权。

### 4.4 成果公开状态

```text
未授权 → 已授权待审核 → 审核通过公开 → 已下架/撤回授权
```

## 七、温暖提示语文案库 V0

### 7.1 文案库建立标准

温暖提示语不是简单“夸孩子”，而是网站教育气质的一部分。文案建立以《教育的目的》的核心理念为基底：教育不是灌输惰性知识，而是让孩子在真实经验中产生兴趣、形成理解、学会运用，并在一次次表达、探索和合作中感到知识是活的。

因此，所有提示语必须符合以下标准：

1. **真诚，不廉价表扬**  
   不泛泛说“你真棒”“太厉害了”，而要具体回应孩子正在做的事：提出问题、讲清思路、帮助同学、完成观察、参与合作。

2. **站在儿童立场**  
   使用孩子能理解、能感受到的语言。语气像一个温柔可信的大人，而不是平台通知、老师训话或成人鸡汤。

3. **有教育引导性**  
   每一句提示都要轻轻指向一种好的学习品质：好奇、思考、表达、倾听、合作、坚持、修正、帮助别人。

4. **承认过程，而不只奖励结果**  
   鼓励孩子看到“提出问题”“愿意讲出来”“修改一次”“和别人合作”本身就是学习的一部分，而不是只有答对、获奖、展示才值得被看见。

5. **保护孩子的勇气**  
   尤其在退回、修改、未通过、超时释放等场景，文案不能让孩子感到羞耻或失败，而要保留继续尝试的空间。

6. **让知识变得有生命**  
   提示语要帮助孩子感觉数学不是冷冰冰的题目，而是可以被发现、表达、使用、分享的东西。

7. **不制造比较和焦虑**  
   不使用“超过别人”“排名提升”“赢过同学”等语言。鼓励来自成长、贡献和真实参与，而不是竞争压力。

#### 推荐语气

- 温暖；
- 具体；
- 轻轻鼓励；
- 有一点儿童友好；
- 有教育意味但不说教。

#### 避免语气

- 空泛鸡汤；
- 过度夸张；
- 成人化训导；
- 排名刺激；
- 把孩子包装成“小大人”；
- 用系统通知口吻代替人的回应。

#### 好提示语公式

```text
看见孩子的动作 + 命名其中的学习价值 + 给出温暖的继续方向
```

示例：

> 你愿意把想不明白的地方说出来，这就是很棒的数学开始。也许你的问题，会帮另一个同学一起想明白。

### 7.2 提问场景

- “感谢你的好问题，让我们的数学更有趣。”
- “你愿意把想不明白的地方说出来，这就是很棒的数学开始。”
- “一个好问题，可能会帮助很多同学一起想明白。”

### 7.3 小讲师场景

- “感谢你帮助了一个同学解惑。”
- “你把自己的思路讲出来，也让别人多了一种想法。”
- “小讲师不是因为完美才勇敢，而是因为愿意分享思考。”

### 7.4 项目场景

- “谢谢你和伙伴一起完成了一次真正的数学探索。”
- “你留下的不只是答案，还有观察、尝试和合作的过程。”
- “这个项目会记录在你的成长护照里。”

### 7.5 审核通过场景

- “你的作品已经通过审核，可以被更多同学看见啦。”
- “这份讲解/成果被保存在你的成长记录里。”
- “谢谢你让数学多了一种孩子自己的表达。”

### 7.6 退回修改场景

退回文案要保护孩子，不使用否定式打击：

- “这次还差一点点，我们一起把它改得更清楚。”
- “老师发现有个地方可以再想一想，修改后还可以继续提交。”
- “这不是失败，只是一次继续完善的机会。”

## 八、开发优先级建议

### 第一步：先做信息架构与静态页面

1. 首页；
2. 你问我答；
3. 项目营；
4. 成果广场；
5. 个人中心入口；
6. 登录弹窗。

### 第二步：做 Q&A 闭环

1. 提交问题；
2. 老师审核；
3. 问题列表；
4. 认领题目；
5. 上传讲解；
6. 讲解审核；
7. 成长记录。

### 第三步：做项目营闭环

1. 项目卡片；
2. 项目详情；
3. 报名/解锁；
4. 协作空间；
5. 成果提交；
6. 项目审核；
7. 项目成长记录。

### 第四步：做后台与分享增强

1. 老师工作台；
2. 管理员权限授权；
3. 公开数据统计；
4. 分享图生成；
5. 成长护照完善。
