## 一、删除项说明的目标

本文件不是代码删除清单，而是产品信息架构层面的“保留、删除、合并、降级”说明。

它回答四个问题：

1. 旧网站或旧页面结构中哪些内容不再作为独立页面或主要信息保留；
2. 为什么删除、合并或降级；
3. 删除后是否迁移到其他页面；
4. 是否影响 P0 MVP。

本文件依据：

- 首页内容清单 V1；
- 分页内容清单 V2；
- 当前代码路由观察；
- 犟爸关于主导航、登录边界、项目营和个人中心的最新决策。

## 四、具体删除项说明

### 1. 删除“登录 / 注册”作为主导航分页

**原状态：**

当前代码存在：

- `/login`
- `/register`

旧结构中容易把登录注册理解成一个主页面入口。

**处理方式：**

不把“登录 / 注册”放入主导航。保留登录注册能力，但产品形态改为：

- 顶部登录按钮；
- 需要登录时弹窗；
- 或保留 `/login` `/register` 技术路由作为兜底。

**删除原因：**

1. 用户不是为了看登录页而来；
2. 登录是动作，不是产品价值入口；
3. 点击“我要提问”“个人中心”“参加项目”等场景时触发登录更自然；
4. 登录后应回到原操作位置，减少跳出。

**迁移去向：**

- 全站登录弹窗 / 抽屉；
- 个人中心未登录拦截；
- 受保护操作触发登录。

**是否影响 MVP：**

不影响。登录注册仍是 P0 能力，只是不作为主导航分页。

---

### 2. 删除“问答广场”命名，统一更名为“你问我答”

**原状态：**

当前产品讨论和部分旧文档中使用“问答广场”。

**处理方式：**

全站统一更名为：

> 你问我答

**删除原因：**

1. “你问我答”更儿童友好；
2. 更直接表达同伴互助关系；
3. 避免和“成果广场”两个“广场”并列造成重复；
4. 弱化平台感，增强参与感。

**迁移去向：**

- 原 `/qa` 页面保留技术路由也可以，但页面标题、导航文案、按钮文案统一改为“你问我答”；
- 后续如调整路由，可考虑 `/ask-answer` 或保留 `/qa` 作为技术路径。

**是否影响 MVP：**

不影响，只影响命名和文案统一。

---

### 3. 删除“上传问题页”作为一级页面

**原状态：**

当前代码存在：

- `/qa/ask`

它是独立路由。

**处理方式：**

不作为主导航或独立一级页面展示。它应归入“你问我答”内部：

> 你问我答 → 我要提问 → 上传问题

**删除原因：**

1. 用户理解上，“上传问题”不是一个独立频道；
2. 它是你问我答中的一个动作；
3. 主导航不应堆积表单类页面；
4. 未登录时应先触发登录弹窗，登录后回到提问动作。

**迁移去向：**

- 你问我答顶部按钮；
- 首页“我要提问”按钮；
- 个人中心“继续提问/我的提问”入口。

**是否影响 MVP：**

不影响。上传问题仍是 P0 必需功能，只是入口归属更清晰。

---

### 4. 删除“问题详情页”作为一级页面

**原状态：**

当前代码存在：

- `/qa/question/[id]`

**处理方式：**

不作为导航页，只作为你问我答中的问题详情子页面。

**删除原因：**

1. 问题详情必须从问题卡片自然进入；
2. 不应作为用户第一层浏览入口；
3. 问题详情承担具体状态和操作，不承担频道说明。

**迁移去向：**

- 你问我答的问题卡片点击进入；
- 个人中心“我的提问/我的讲解”点击进入。

**是否影响 MVP：**

不影响。问题详情是 P0 子功能，继续保留。

---

### 5. 删除“上传讲题页”作为一级页面

**原状态：**

当前讲解上传依赖问题详情或相关回答流程。

**处理方式：**

上传讲题不做公开入口，而是认领成功后的内部动作：

> 认领题目 → 系统锁定 → 上传讲解视频

**删除原因：**

1. 不能让孩子脱离问题直接上传讲题；
2. 上传讲题必须依附于已认领的问题；
3. 防止用户误解为普通视频投稿；
4. 符合“自主认领 + 系统锁定 + 发布前审核”的机制。

**迁移去向：**

- 问题详情中的“上传讲解”；
- 个人中心“待提交讲解任务”。

**是否影响 MVP：**

不影响。上传讲题仍是 P0 必需动作。

---

### 6. 删除“项目营只作为普通介绍页”的旧处理

**原状态：**

当前代码中 `/projects` 更像项目列表页，容易被理解为普通课程/项目列表。

**处理方式：**

项目营升级为 P0 主场景页，承载：

- 项目营介绍；
- 项目样例；
- 可参加项目；
- 项目任务书；
- 项目协作空间；
- 项目成果提交。

**删除原因：**

1. 犟爸已明确问答闭环和 PBL 都是 P0；
2. 项目营不是普通课程列表，而是核心学习场景；
3. PBL 是孩子从讲题进入合作探索的关键路径。

**迁移去向：**

- 主导航“项目营”；
- 内部包含项目任务书和协作空间。

**是否影响 MVP：**

影响 P0。项目营必须保留，但可以先做轻量版。

---

### 7. 删除“公开所有项目正式任务”的设想

**原状态：**

如果项目营公开所有项目和任务书，容易让未登录用户看到完整任务细节。

**处理方式：**

采用三层公开：

1. 未登录公开：项目营介绍、项目样例、已授权成果；
2. 登录后可看：可参加项目、基础任务说明、孩子参与项目状态；
3. 参与后可进入：正式任务书、协作空间、小组信息、过程记录、成果提交。

**删除原因：**

1. 正式任务书是项目体验核心；
2. 协作空间涉及孩子隐私；
3. 小组成员和过程记录不适合公开；
4. 公开样例已足够建立家长理解。

**迁移去向：**

- 公开内容放项目营介绍；
- 正式内容放参与后项目空间。

**是否影响 MVP：**

不影响。反而让 P0 权限边界更清晰。

---

### 8. 合并“家长进度页”和“成长中心”，统一为“个人中心”

**原状态：**

V0 曾拆分：

- 个人中心 / 成长护照；
- 家长进度页。

**处理方式：**

合并为：

> 个人中心

内部可保留模块：

- 我的成长护照；
- 我的提问；
- 我的讲解；
- 我的项目；
- 积分与徽章；
- 家长设置；
- 隐私授权；
- 老师反馈。

**删除原因：**

1. 小学一、二年级孩子通常不能独立登录和管理账号；
2. 家长帮助注册并共同使用账号更符合现实；
3. 拆成两个页面会造成导航复杂和数据重复；
4. 一个“个人中心”入口可根据角色显示不同内容。

**迁移去向：**

- 家庭账号 → 孩子/家长共同的个人中心；
- 老师账号 → 老师工作台。

**是否影响 MVP：**

不影响，降低复杂度。

---

### 9. 删除老师审核页的公开导航入口

**原状态：**

当前代码中 Navbar 对老师/管理员显示“老师台”。

**处理方式：**

老师工作台不进入普通公开导航。老师登录后：

- 自动跳转老师工作台；
- 或点击个人中心进入老师工作台。

**删除原因：**

1. 老师审核是后台能力，不是公开产品入口；
2. 普通家庭用户不应该看到或感知后台结构；
3. 角色跳转比公开导航更清晰；
4. 权限边界更安全。

**迁移去向：**

- 老师账号登录后的个人中心 / 老师工作台。

**是否影响 MVP：**

不影响。老师审核仍是 P0，只是不公开导航展示。

---

### 10. 删除首页中的长文式说明

**原状态：**

首页 V0 信息容易被理解为完整文稿，文字量偏大。

**处理方式：**

首页不承载长文解释，改为：

- 短句；
- 标签；
- 卡片；
- 流程图；
- 精选成果；
- 明确行动按钮。

**删除原因：**

1. 首页不是说明书；
2. 家长需要快速判断，而不是读长文；
3. 长文会弱化行动入口；
4. 视觉上会像文稿，不像产品首页。

**迁移去向：**

- 详细规则进入你问我答 / 项目营 / 个人中心；
- 理念说明可放首页卡片或后续“家长了解”模块，但不作为长文主内容。

**是否影响 MVP：**

不影响，提升首页转化。

---

### 11. 删除首页完整积分规则

**原状态：**

积分规则容易被完整搬到首页。

**处理方式：**

首页只保留原则：

- 提问通过审核可获得小积分；
- 积分自己可见；
- 徽章可公开；
- 无排行榜。

完整积分流水进入个人中心，异常和统计进入老师后台。

**删除原因：**

1. 完整积分规则信息量过大；
2. 容易让产品像游戏化积分平台；
3. 首页应强调成长，不强调算分；
4. 公开积分会制造比较焦虑。

**迁移去向：**

- 个人中心积分流水；
- 老师后台积分管理；
- 必要时设“积分说明”弹窗。

**是否影响 MVP：**

不影响。

---

### 12. 删除公开排行榜 / 公开积分展示

**原状态：**

如果成果广场或个人中心展示公开积分、排名、Top 榜，会违背低焦虑原则。

**处理方式：**

不做公开排行榜，不展示他人积分。

**删除原因：**

1. 与反焦虑底线冲突；
2. 容易诱导刷题、抢答、刷积分；
3. 会让家长产生比较心理；
4. 不符合“作品展览墙”定位。

**迁移去向：**

- 积分仅自己和家长可见；
- 公开展示徽章、作品、成长片段；
- 老师后台可看统计和异常。

**是否影响 MVP：**

不影响，且必须删除。

---

### 13. 删除未授权成果展示

**原状态：**

成果广场可能展示讲题视频和已解决问题，但需要补充授权边界。

**处理方式：**

成果广场只展示：

- 老师审核通过；
- 家庭授权公开；
- 已做隐私保护；
- 不包含敏感信息的成果。

**删除原因：**

1. 孩子视频和作品涉及隐私；
2. 未授权公开会造成家长信任风险；
3. 成果广场是公开页面，必须更严格；
4. 公开内容应保护真实姓名、学校、联系方式等信息。

**迁移去向：**

- 未授权成果只在个人中心自己可见；
- 授权后进入成果广场。

**是否影响 MVP：**

不影响，但需要权限和字段支持。

---

### 14. 删除 SecurityGuard 的强拦截体验

**原状态：**

当前 `app/layout.tsx` 引入 `SecurityGuard`。评审文档指出其禁止右键和选择文本，会伤害可用性和无障碍。

**处理方式：**

建议删除或弱化，不做全站禁止复制、禁止右键、禁止选择。

**删除原因：**

1. 家长和老师可能需要复制问题文本；
2. 孩子可能需要选中文字；
3. 禁止右键不能真正保护内容；
4. 会造成可用性和无障碍问题。

**迁移去向：**

- 版权和隐私靠授权机制、审核机制、内容水印和用户协议，而不是全站禁用操作。

**是否影响 MVP：**

不影响，建议尽早处理。

---

### 15. 删除 alert 弹窗反馈

**原状态：**

当前老师审核等操作中使用 `alert()` 反馈。

**处理方式：**

替换为：

- Toast；
- 页面内状态提示；
- 按钮 loading；
- 审核结果反馈条。

**删除原因：**

1. alert 打断操作；
2. 不适合孩子和老师频繁使用；
3. 无法承载温和反馈；
4. 体验显得粗糙。

**迁移去向：**

- 统一提示组件；
- 老师审核页内联反馈。

**是否影响 MVP：**

不影响，但能明显提升体验。

---

### 16. 删除重复或过重的移动端菜单结构

**原状态：**

评审文档指出移动端 Navbar 可能存在重复汉堡按钮结构和入口复杂问题。

**处理方式：**

移动端主入口统一为：

- 首页；
- 你问我答；
- 项目营；
- 成果广场；
- 个人中心。

必要时采用底部 Tab 或简洁抽屉，不重复显示多个菜单按钮。

**删除原因：**

1. 家长移动端使用频繁；
2. 孩子低龄，入口不能复杂；
3. 重复菜单增加误触和困惑；
4. 主导航已经收敛，不需要复杂层级。

**迁移去向：**

- 统一 Navbar / MobileNav 组件。

**是否影响 MVP：**

不影响。

## 五、页面级处理建议

### 5.1 当前代码路由与新结构映射

| 当前路由 | 当前含义 | 新结构处理 |
