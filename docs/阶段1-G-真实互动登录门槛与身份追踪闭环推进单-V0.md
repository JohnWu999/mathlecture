## 1. 阶段判断

阶段1-F已经解决“入口不能是假入口、状态反馈不能假反馈、未完成能力必须诚实降级”的问题。

阶段1-G要解决的是：

> 用户只要参与真实互动，就必须有可追踪身份；否则老师讲解、审核反馈、视频推送、采纳记录、成长能量和项目权限都无法形成后台闭环。

因此，本阶段的业务规则确定为：

> **公开内容可以浏览；真实互动必须登录注册。**

这不是提高无意义门槛，而是为了保证第一批试运营数据可追踪、反馈可送达、老师工作台可闭环、个人中心可沉淀。

---

## 2. 权限边界总原则

### 2.1 未登录用户可以访问

未登录用户可以低门槛浏览公开内容：

1. 首页
   - 平台介绍
   - 教育理念
   - 项目亮点
   - 公开入口

2. 成果广场
   - 已公开授权成果
   - 空状态说明
   - 审核/授权边界说明
   - 不允许投稿、授权、点赞、评论或提交作品

3. 你问我答部分内容
   - 公开问题列表
   - 已审核公开讲解
   - 提问规则说明
   - 不能直接提问、采纳、提交讲解

4. 项目营部分内容
   - 项目简介
   - 适合年级
   - 学习目标
   - 体验说明
   - 不能报名、加入、提交项目成果或查看个人项目权限

### 2.2 必须登录后才能执行

以下动作必须绑定注册账号：

1. 发起提问
2. 提交讲解
3. 采纳讲解
4. 报名项目营或加入项目
5. 提交项目成果
6. 申请公开授权或撤回授权
7. 查看个人中心 / 成长护照 / 项目权限
8. 任何会产生后台记录、审核状态、成长记录、推送任务、项目权限或付费/权益状态的动作

## 3. 为什么不再允许匿名提问

之前允许未注册用户提问题，优点是降低门槛；但进入真实试运营后，缺点会直接伤害业务闭环：

1. **无法追踪提问者**  
   老师讲解完成后，系统无法稳定知道应该把讲解视频和反馈推送给谁。

2. **无法形成完整问答闭环**  
   提问 → 小讲师讲解 → 老师审核 → 推送提问者 → 提问者采纳 → 成长记录，这条链路必须有账号身份。

3. **无法复盘真实运营数据**  
   后台无法准确统计谁提问、谁参与、谁被讲解、谁采纳、谁适合进入项目营。

4. **容易产生无效数据**  
   匿名提问容易产生无法回访、无法确认来源、无法处理后续反馈的无效问题。

5. **不利于保护孩子作品和互动安全**  
   真实互动必须可审核、可追溯、可回访。

## 4. 阶段1-G P0工作拆解

### P0-1｜提问入口登录化

目标：`/qa/ask` 不再允许未登录用户直接提交问题。

验收口径：

- 未登录访问 `/qa/ask` 时，可以看到提问规则与登录说明，但不能提交问题。
- 页面必须说明：登录是为了让老师讲解完成后可以把反馈准确推送给提问者。
- 页面提供“去登录 / 注册”入口。
- 登录成功后建议保留回跳提问页能力。
- 后端创建问题接口必须拒绝匿名创建。

建议提示文案：

```text
提问需要登录后进行。这样老师讲解完成后，我们才能把讲解视频和反馈准确推送给你。
```

### P0-2｜你问我答公开页分层

目标：`/qa` 可以公开浏览，但互动动作必须登录。

验收口径：

- 未登录用户可以浏览公开问题列表与已审核公开讲解。
- 未登录用户点击“我要提问”时进入登录提示或登录页。
- 未登录用户不能采纳讲解、提交讲解、认领讲解任务。
- 所有按钮必须给出真实动作或明确说明，不能出现假按钮。

### P0-3｜项目营公开页分层

目标：`/projects` 与 `/projects/[id]` 公开展示项目信息，但参与动作必须登录。

验收口径：

- 未登录用户可以浏览项目简介、适合年级、学习目标、体验说明。
- 未登录用户不能报名、加入、提交任务、提交作品或查看个人项目权益。
- 点击参与类按钮时必须进入登录提示或登录页。
- 公开展示继续沿用阶段1-F的价格真实性规则：`PAID + price<=0` 公开侧归一为免费体验/试运营状态。

### P0-4｜后端API权限统一

目标：统一 GET 公开、写入动作登录的后端边界。

重点复核接口：

```text
/api/questions
/api/answers
/api/answers/[id]/approve
/api/projects/[id]/register
/api/outcomes
/api/user/profile
/api/teacher/*
/api/admin/*
```

验收口径：

- 公开 GET 可以保留开放，但只返回已审核、可公开内容。
- POST / PUT / PATCH / DELETE 等写入动作必须有 session。
- 匿名请求不能创建问题、讲解、报名、成果、授权、采纳记录。
- 受保护接口未登录返回 401 或跳登录，不能静默写入。

### P0-5｜身份追踪与后台字段自检

目标：确认真实互动数据都能回溯到用户。

验收口径：

- Question 必须能追踪提问者。
- Answer 必须能追踪小讲师/提交者。
- 采纳动作必须能追踪采纳者。
- ProjectAccess / Enrollment / Outcome 必须能追踪用户与项目。
- 老师后台能看到需要处理的真实记录，不展示匿名脏数据作为主要任务。

### P0-6｜页面文案诚实降级

目标：所有未登录互动入口都给出诚实说明，而不是简单报错。

统一文案原则：

```text
你可以先浏览公开内容。
如果想提问、报名项目、提交讲解或查看老师反馈，需要注册/登录账号。
```

## 5. 第一轮审计清单

进入阶段1-G后，先做一轮代码与公网审计，不直接大改。

### 5.1 页面审计

重点页面：

```text
/
/login
/qa
/qa/ask
/qa/question/[id]
/projects
/projects/[id]
/hall
/profile
/teacher
/admin
```

检查项：

- 未登录是否可以浏览公开内容。
- 未登录是否可以触发真实互动。
- 互动按钮是否是假按钮。
- 登录提示是否说明为什么需要登录。
- 登录后是否能回到原目标动作或目标页面。

### 5.2 API审计

重点接口：

```text
/api/questions
/api/answers
/api/answers/[id]/approve
/api/projects/[id]/register
/api/hall
/api/projects
/api/user/profile
/api/teacher/outcomes
```

检查项：

- GET 是否只返回可公开内容。
- POST / PATCH / PUT / DELETE 是否必须登录。
- 未登录写入动作是否 401。
- 是否存在匿名创建问题、匿名提交讲解、匿名报名、匿名成果提交路径。

### 5.3 数据审计

检查项：

- 历史问题是否存在无用户归属的记录。
- 历史讲解是否存在无用户归属的记录。
- 项目权限是否都绑定 User。
- 成果是否都绑定 User / Project。
- 是否需要对历史匿名数据做保守归档或只读保留。

## 6. 不属于阶段1-G的事项

以下事项暂不纳入阶段1-G，避免范围失控：

1. 正式支付系统接入。
2. 短信验证码或第三方登录重构。
3. 家长账号 / 孩子账号复杂绑定体系。
4. 消息推送系统全量实现。
5. 历史测试账号批量归档或删除。
6. 成果广场评论、点赞、复杂社交互动。
7. 项目营完整任务协作空间重构。

阶段1-G只解决：

> 公开浏览与真实互动的身份边界，以及后台可追踪闭环。

## 7. 阶段验收标准

阶段1-G完成时，必须满足：

1. 未登录用户仍可浏览首页、成果广场、问答公开内容、项目营公开简介。
2. 未登录用户不能创建问题、提交讲解、采纳讲解、报名项目、提交成果、申请授权。
3. 所有真实互动写入 API 均要求 session。
4. 所有未登录互动入口都有页面内说明或登录跳转，不出现假按钮。
5. 后台数据可以追踪到具体用户。
6. 规则测试通过。
7. `npm run build` 通过。
8. 部署上线并完成公网验证。
9. PM2 online，unstable restarts=0。
10. 生成阶段1-G最终交付文档。
