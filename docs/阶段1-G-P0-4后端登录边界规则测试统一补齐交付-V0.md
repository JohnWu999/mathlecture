## 2. 新增测试

新增文件：

```text
tests/stage1g-p04-backend-auth-boundary-rules.test.mjs
```

测试分四组：

1. **所有 state-changing API 路由必须被分类**
   - 扫描 `app/api/**/route.ts` 中所有 `POST/PATCH/PUT/DELETE`；
   - 要么归入登录绑定路由；
   - 要么明确列入有意公开的例外。

2. **登录绑定 mutation 路由必须检查 session 并具备 401 边界**
   - 直接使用 `getServerSession(authOptions)`；或
   - 通过 `requireAdmin()` 间接继承 401 / 403 边界。

3. **用户生成或权益写入必须绑定 session 身份**
   - 如 `authorId: session.user.id`、`lecturerId: session.user.id`、`userId: session.user.id`、`uploaderId: session.user.id` 等。

4. **老师 / 管理员 mutation 必须有角色边界**
   - 老师接口检查 `TEACHER`；
   - 管理员接口使用 `requireAdmin()`；
   - 错误角色返回 403。

## 4. 红灯与修正说明

新增集中测试后首次运行，出现 1 个失败：

```text
app/api/admin/project-access/route.ts should return HTTP 401 for anonymous writes
```

原因不是业务代码缺少保护，而是测试最初只在具体 admin route 中查找 `status: 401`；实际 admin route 通过 `requireAdmin()` 统一继承 401 / 403。随后修正测试逻辑：

- 对普通登录绑定路由：在当前 route 中检查 `status: 401`；
- 对 `requireAdmin()` 路由：检查 `lib/admin-auth.ts` 中的 401 / 403 边界。

修正后 P0-4 单测通过。
