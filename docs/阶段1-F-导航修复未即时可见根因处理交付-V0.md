# 阶段1-F｜导航修复未即时可见根因处理交付 V0

时间：2026-06-09 09:38 CST

## 1. 本轮反馈

犟爸反馈：“没看到你修复后的效果”。

本轮不再继续凭代码判断，而是按线上可见性问题处理：检查公网响应、缓存头、线上 HTML 引用的静态资源与 CSS 内容。

## 2. 根因自检

自检发现：上一轮代码和部署已经进入线上包，但用户端可能仍看不到新效果，核心原因是导航样式主要落在前端 JS/styled-jsx chunk 中，而公共页面此前仍有静态页面缓存迹象。

线上检查中看到：

- `/qa`、`/projects`、`/hall` 等公共导航页面返回 `x-nextjs-cache: HIT`；
- 这些页面此前未统一加 `no-store`；
- 浏览器可能继续复用旧页面壳或旧导航样式 chunk；
- 结果就是服务器已换包，但用户端看起来仍像旧效果。

因此问题不只是“Logo 再缩一点”，而是“修复后的导航样式没有稳定强制刷新到用户端”。

## 3. 本轮修复

### 3.1 公共导航页面统一 no-store

修改 `middleware.ts`：

- 将以下带导航的公共页面纳入 `no-store`：
  - `/`
  - `/qa`
  - `/projects`
  - `/hall`
  - `/login`
  - `/profile`
- matcher 补充 `/`，确保首页也经过 middleware。

缓存头统一为：

```txt
Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0
Pragma: no-cache
Expires: 0
```

### 3.2 加入全局 CSS 兜底覆盖

修改 `app/globals.css`，新增 Stage1-F 导航即时可见兜底覆盖：

- `.forest-site-nav .forest-brand` 强制宽度 `76px`，居中，`gap: 0`；
- `.brand-logo-mark` 默认强制 `22px × 14px`；
- 桌面端强制 `24px × 15px`；
- 手机端强制 `20px × 13px`；
- `.brand-title` 强制居中、紧贴 Logo 下方；
- `.forest-site-nav .login` 强制独立边框：
  - `border: 2px solid #184638 !important`
  - `box-shadow: 0 0 0 4px rgba(255, 209, 102, 0.32) !important`

这样即便旧 JS 样式还在浏览器里，新 CSS 文件也能强制覆盖 Logo 和登录按钮视觉。
