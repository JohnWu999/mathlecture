## 二、阶段2最终产品结构

### 2.1 主导航

主导航最终保留 5 个入口：

1. 首页；
2. 你问我答；
3. 项目营；
4. 成果广场；
5. 个人中心。

不进入主导航的内容：

- 登录 / 注册；
- 上传问题；
- 上传讲解；
- 问题详情；
- 项目任务书；
- 项目协作空间；
- 老师工作台；
- 管理后台。

这些功能作为场景内按钮、弹窗、子页面或登录后的角色后台存在。

### 2.2 账号与角色

最终采用三类账号：

1. **学习者账号**  
   即孩子账号，孩子是主体，家长只辅助上传、授权、支付、确认等操作。

2. **老师账号**  
   通过“个人中心”进入老师工作台，负责审核、能力标签、退回原因、项目节点查看等。

3. **管理员账号**  
   通过“个人中心”进入管理后台，负责用户、项目、权限、内容和数据管理。

个人中心是统一入口，根据登录身份分流。

## 三、首页最终结构

### 3.1 首页任务

首页不是完整说明书，而是让第一次进入的家长和孩子在约 30 秒内理解：

1. 这是什么；
2. 适不适合我家孩子；
3. 孩子在这里怎么学；
4. 和刷题、补课、AI答疑有什么不同；
5. 有没有真实成果可以看；
6. 如何开始。

### 3.2 首页模块

首页最终采用 7 个模块：

1. 首屏定位区；
2. 孩子怎么学；
3. 适合谁 / 不太适合谁；
4. 你问我答预览；
5. 项目营预览；
6. 精选成果预览；
7. 安全、审核与低焦虑承诺。

### 3.3 首屏定位

- 产品名：数学小讲师联盟；
- Slogan：会思考，爱数学；
- 副标题：小学低年级孩子的数学共学社区；
- 标签：小学1–3年级｜同伴互助｜项目制学习｜低焦虑成长。

定位说明：MVP种子用户仍以小学一年级下到二年级上为主，但对外人群定位写成“小学低年级/小学1–3年级”，为后续项目难度、年级拓展和产品升级预留空间。

### 3.4 首页首屏按钮

最终保留两个按钮：

| 按钮 | 指向 | 说明 |
|---|---|---|
| 我要提问 | 你问我答中的提交问题流程 | 行动入口，未登录时弹登录/注册 |
| 看看孩子怎么学 | 首页内部“孩子怎么学”模块 | 理解入口，不新开复杂页面 |

“我要讲题”不放在首页首屏，避免新用户尚未理解问答机制时产生困惑。小讲师入口放在你问我答场景中表达为“我要当小讲师”或“去认领一道题”。

### 3.5 首页公开数据

首页可展示平台级温暖数据，例如：

- 已有多少个好问题被提出；
- 已有多少个问题被小讲师解答；
- 已有多少位孩子参与项目探索；
- 已有多少个小组完成协作。

边界：展示鼓舞型群体数据，不展示个人排名和积分。

## 四、你问我答页面最终结构

### 4.1 页面任务

你问我答承担：

1. 展示已审核问题；
2. 让孩子提交真实问题；
3. 让孩子自主认领可讲的问题；
4. 展示已发布讲解；
5. 形成提问者和小讲师的成长记录。

### 4.2 页面模块

1. 页面标题与说明；
2. 操作入口区；
3. 问题列表；
4. 已发布讲解列表；
5. 问题详情子页面；
6. 提交问题流程；
7. 认领问题与上传讲解流程。

### 4.3 顶部操作入口

| 按钮 | 实际进入 | 说明 |
|---|---|---|
| 我要提问 | 提交问题流程 | 提交后进入审核 |
| 我要当小讲师 | 可认领问题列表 | 不是直接上传视频，而是先选题再讲 |

### 4.4 问题卡片信息

每张问题卡片展示：

- 问题标题；
- 年级 / 主题标签；
- 问题简述；
- 状态：待认领 / 已认领 / 已讲解；
- 提问者昵称与主身份轻展示；
- 按钮：查看详情 / 我来讲。

### 4.5 提交问题流程

1. 登录检查；
2. 填写问题标题；
3. 上传题目图片或输入文字；
4. 选择年级 / 主题；
5. 补充“我哪里想不明白”；
6. 提交审核；
7. 显示温暖提示语；
8. 审核通过后进入你问我答。

提交问题页面要求：

- 必须有“上传图片 / 拍照原题”按钮；
- 页面提示孩子或家长尽量拍清楚原题，因为原题图片最准确；
- 系统应保存题目图片进入问题题库；
- 后续可做OCR/AI识别，自动提取题目文字、知识点、题型信息；
- MVP阶段可以先保存图片和人工/半自动标注，图片识别作为后续增强。

温暖提示示例：

> 感谢你的好问题，让我们的数学更有趣。

### 4.6 我要当小讲师流程

1. 进入可认领问题列表；
2. 选择一道问题；
3. 弹出“小讲师认领贴士”；
4. 孩子确认后系统自动锁定；
5. 48小时内上传讲解视频；
6. 超过48小时未上传，题目自动释放；
7. 老师审核数学正确性、表达清晰度、内容安全；
8. 审核通过后发布或进入个人成长记录；
9. 显示温暖提示语。

### 4.7 小讲师认领贴士

认领前以“小约定”形式展示：

- 认领后请在48小时内上传讲解视频；
- 48小时内未上传，题目会自动释放；
- 遇到特殊情况，可以请家长协助说明；
- 无故放弃累计3次后，暂停一段时间的认领资格；
- 讲解视频要尽量清楚：能看到题目、能听清声音、能讲出思考过程；
- 不要求一次讲得完美，重点是愿意思考、愿意表达、愿意帮助别人。

### 4.8 视频分享范围选择

孩子上传讲解视频时，不采用冷冰冰的“勾选同意授权”，而采用更有意义感的分享范围选择，让孩子和家长感到分享是在帮助别人。

建议选项：

> A. 只分享给出题的同学，帮助他/她理解这个问题。  
> B. 我愿意分享给更多同学，也许能给大家带来一点启发。

规则：

- 选择A：讲解视频只对出题人、老师和本人可见，并进入个人成长记录；
- 选择B：老师审核通过后，可进入成果广场；必要时仍需家长确认；
- 两个选项都不使用“授权协议式”冷表达，而用“帮助谁、启发谁”的儿童可理解语言；
- 无论选择A或B，老师都要先审核数学正确性、表达清晰度、内容安全。

提示文案示例：

> 你的讲解可以只帮助这位同学，也可以被更多同学看见。愿意分享，是因为你的思路可能会点亮别人的想法。

### 4.9 问题热度与帮助人数统计

问题卡片或问题详情页可以设置“我也有这个困惑 / 加一点热度”按钮。

规则：

- 如果另外5个同学也觉得自己有同样困惑，可以为该题增加热度；
- 热度高的问题可以在可认领列表中适当靠前，帮助小讲师优先选择更能帮助大家的问题；
- 当该问题有讲解视频并审核通过后，系统可把讲解推送给提问者和所有加过热度的同学；
- 小讲师帮助人数可计算为：1位提问者 + 加热度人数；例如提问者1人、加热度5人，则本次讲解帮助6人；
- 帮助人数进入小讲师成长护照，但不做公开排行榜。

通知能力：

- MVP阶段至少在站内“我的消息/个人中心”中显示；
- 如果推送系统复杂，可后续升级短信、微信、邮件或飞书式通知。

## 五、项目营页面最终结构

### 5.1 页面任务

项目营承担：

1. 展示基础项目和进阶项目；
2. 让孩子参与真实数学项目；
3. 形成探索家身份和项目成果；
4. 承接主要付费业务。

### 5.2 页面模块

1. 项目营介绍区；
2. 免费基础项目区；
3. 进阶项目 / 主题项目营区；
4. 项目成果预览；
5. 项目参与规则说明；
6. 项目详情 / 任务书 / 协作空间子页面。

### 5.3 项目卡片信息

每个项目卡片展示：

- 项目名称；
- 适合年级；
- 项目主题；
- 核心知识点标签，例如面积、周长、测量、图形分割、统计、规律；
- 能力标签，例如画图表达、动手制作、小组合作、观察记录、讲清楚思路；
- 预计周期；
- 当前状态：可报名 / 进行中 / 已结束；
- 解锁条件：积分、前置项目、是否付费等；
- 组队状态：第一组已加入2名，还缺1名即可组团；第二组已加入1名，还缺2名即可组团；
- 有效时长：如解锁后1个月内完成，完成后可永久回看；
- 已参与人数 / 已完成小组数等项目级数据；
- 按钮：查看介绍 / 报名参加。

标签展示原则：每张卡片最多展示2–4个核心标签，帮助孩子判断方向，不把卡片变成成人化说明书。

解锁条件原则：

- 免费项目可以设置低门槛积分解锁，例如低难度20积分、中等难度30积分；
- 积分只作为私密成长账本和项目参与门槛，不做公开排名；
- 付费项目可设置“积分/前置项目 + 付费解锁”的组合条件，例如满30积分或完成若干免费项目后，可报名付费项目；
- 解锁条件要表达为“你已经准备好挑战这个项目”，而不是“分数不够不能参加”。

组队状态原则：

- 项目以小组为单位时，页面可展示当前组队进度：如“第一组已加入2名，还缺1名即可组团”；
- MVP阶段若能力标签不足，按报名顺序自动组队，例如1–3名一队、4–6名一队；
- 后续有能力标签后，可结合报名顺序、年级、能力标签、参与历史进行自动组队；
- 组队信息不做能力比较，不展示“强弱”标签，只展示组队进度和参与状态。

### 5.4 免费项目与付费项目边界

#### 免费基础项目

- P0 建议开放1–3个免费基础项目，成熟后扩展到1–5个；
- 采用异步轻协作；
- 以自主体验、系统节奏、过程上传、自动结营证书为主；
- 老师不默认组织线上视频会，不默认提供长篇个性化点评。

重要边界：免费基础项目也必须是高水准项目，不能做成“低质量试用品”。免费与付费的区别主要在于：复杂程度、知识点难度、项目组织密度、老师参与深度和个性化反馈，而不是质量高低。

#### 付费进阶项目 / 主题项目营

- 可包含同步启动、破冰、中期展示、结营展示；
- 可包含老师节点提醒和个性化贡献反馈；
- 可承接主要付费业务，用项目收入反哺免费社区审核成本。

### 5.5 项目营权益与体验特色对比

项目营页面需要单独展示“免费项目”和“付费项目”各自包含的权益与体验特色，帮助家长做选择，也降低反复咨询成本。

| 类型 | 适合对象 | 包含内容 | 老师参与 | 反馈方式 | 典型价值 |
|---|---|---|---|---|---|
| 免费基础项目 | 第一次体验、想尝试项目制学习的孩子 | 基础任务书、结构化协作空间、系统节奏提醒、成果提交、自动证书 | 主要负责审核、安全、必要标签 | 自动化反馈为主 | 低门槛体验真实数学项目 |
| 付费进阶项目 / 主题项目营 | 愿意持续参与、希望获得更完整项目体验的孩子 | 进阶任务书、组队协作、关键节点提醒、展示环节、结营证书 | 可包含老师指导、节点跟进、展示组织 | 个性化贡献反馈、家长可读总结 | 更完整的PBL项目体验和成长反馈 |

展示原则：

- 不贬低免费项目；免费项目是完整体验的入口；
- 不夸大付费项目；付费项目强调更完整的陪伴、节点和反馈；
- 清楚说明哪些服务在免费项目不默认提供，避免家长期待错位。

### 5.6 付费项目报名与付款信息

付费项目点击报名时，MVP阶段建议采用“报名意向 + 老师/管理员联系 + 付款信息”的方式，而不是直接只弹付款码。

推荐流程：

1. 家长点击“报名/解锁付费项目”；
2. 弹出付费项目说明：价格、周期、包含权益、适合对象、开营时间；
3. 家长填写或确认联系方式、孩子信息、想报名的项目；
4. 页面展示老师微信二维码或报名老师联系方式；
5. 老师/管理员第一时间获得家长报名信息；
6. 家长付款后，由管理员手动开通项目权限；
7. 后续规模化后，再接入自动支付解锁。

原因：早期项目需要老师及时了解家长信息、孩子情况和项目匹配度，直接付款码容易丢失沟通机会，也不利于早期服务质量控制。

### 5.7 项目有效期与组队后开启协作台

付费项目报名时，项目开展和结束时间可能无法完全固定，因为需要等待组队成功。因此采用“解锁有效期 + 组队成功后开启协作台”的规则。

建议规则：

- 家长付费/项目解锁后，孩子进入等待组队状态；
- 页面显示当前组队进度，如“还缺1名队员即可开组”；
- 组队成功后，系统自动开启项目协作台；
- 每个项目设置一定有效时长，例如解锁后1个月内完成；
- 若在有效期内完成项目，显示“解锁成功/项目完成”，项目资料、过程记录、成果和证书可永久回看；
- 若超过有效期未完成，项目参与资格失效或需申请延期；
- 具体延期/退款规则需要在报名前明确告知。

### 5.8 项目详情页可见边界

未登录可见：

- 项目介绍；
- 样例成果；
- 适合谁；
- 需要准备什么。

登录后可见：

- 报名状态；
- 是否已解锁；
- 任务节奏；
- 提交入口。

参与 / 解锁后可见：

- 正式任务书；
- 协作空间；
- 小组成员；
- 过程记录；
- 成果提交；
- 节点提醒。

### 5.9 项目认领 / 报名前的小约定

点击报名或认领项目前，弹出认领贴士：

- 认领项目后，请认真参与，不要随意退出；
- 如果确实有特殊情况，可以请家长帮忙说明；
- 无故退出累计3次后，将暂停一段时间的免费项目认领资格；
- 完成项目后，可以获得项目结营证书，并记录到成长护照；
- 免费项目主要鼓励自主体验；付费项目会有老师指导、节点提醒和个性化反馈。

按钮：

- 我知道了，开始认领；
- 我再想想。

### 5.10 请假退出与资源释放

项目认领、题目认领后，需要提供“请假退出”按钮，让孩子/家长在确实无法继续时有体面退出的路径。

题目认领退出：

- 点击请假退出后，题目自动释放给其他小讲师；
- 正常请假不计入无故放弃；
- 无说明放弃、超时不上传，可计入无故放弃记录。

免费项目退出：

- 正常请假退出不公开、不羞辱；
- 无故退出累计3次后暂停新的免费体验项目机会。

付费项目退出：

- 可行，但必须在报名前明确规则，并由家长确认；
- 建议规则：项目正式开始前可申请取消或延期；项目开始后请假退出可扣除一半费用；无故退出或长期不参与可扣除本次项目全部费用；
- MVP阶段退款/扣费可先人工处理，不必一开始做自动退款系统；
- 所有规则要用清楚、温和、家长可理解的方式展示，避免争议。

### 5.11 协作空间最终结构

MVP阶段采用结构化协作空间，而不是复杂在线协作文档。

协作空间包含：

1. 老师公告区：项目目标、本周任务、注意事项；
2. 任务卡片区：谁负责观察、画图、讲解、整理等；
3. 小组留言 / 聊天区：支持文字、图片，必要时家长辅助输入；
4. 作品上传区：草稿、图片、视频、文档；
5. 项目进度区：已加入、已分工、已提交草稿、已完成作品、老师已点评、已结营；
6. 成果墙；
7. 自动结营证书。

所有核心交流、提交、点评、节点记录都应能在后台留痕和存档。AI智能分析作为后续增强。

### 5.12 项目成果分享范围选择

项目成果提交页同样采用价值导向的分享范围选择：

> A. 只保存在我的成长护照和项目小组记录中。  
> B. 我愿意分享给更多同学和家长，展示我们小组的数学探索。

规则：

- 选择A：成果进入个人/小组记录、成长护照和老师后台，不进入公开成果广场；
- 选择B：老师审核通过后，可进入成果广场；必要时仍需家长确认；
- 分享文案强调“给别人启发”和“展示探索过程”，而不是“曝光”“推广”。

### 5.13 成果提交形式与结营证书

项目成果提交需要匹配小学低年级孩子的表达能力，不强迫孩子完成成人化报告。

成果提交形式建议：

- 照片：适合展示测量记录、图形作品、手工作品、草稿纸、观察表；
- 短视频：适合孩子讲解项目过程、展示实验、说明小组发现；
- 语音+图片：适合低龄孩子不方便打字时表达；
- 简短文字：家长可辅助输入，但尽量保留孩子自己的表达；
- 项目模板：平台提供“我观察到…… / 我发现…… / 我们小组做了……”式轻量结构。

推荐策略：

- 免费基础项目：照片 + 简短说明即可完成；可选短视频；
- 付费进阶项目：建议照片/视频 + 过程说明 + 小组成果展示；
- 老师审核时关注数学过程、表达清楚度和安全，不把作品包装成成人化展示。

结营证书需要展示孩子在项目中收获的能力，例如：

- 观察记录；
- 画图表达；
- 测量与比较；
- 讲清楚思路；
- 小组合作；
- 坚持完成；
- 提出好问题。

证书上的能力来自老师的能力观察记录、项目任务完成情况和提交成果，不公开具体积分或后台标签。

### 5.14 项目完成后的儿童视角反馈问卷

每次项目完成后，建议设置一个简短的孩子意见反馈问卷，由孩子为主体填写，家长可辅助完成。

设计目标：

- 让孩子回看自己的真实体验；
- 帮助平台理解项目难度、协作体验和任务设计是否合适；
- 为老师和管理员提供改进依据；
- 后续可用于生成项目反馈摘要和成长护照中的项目反思。

MVP问卷形式：

- 3–5个儿童可理解的问题；
- 可用表情、星星、单选、多选、简短文字；
- 家长可辅助输入，但问题应面向孩子；
- 允许孩子用一句话说“我最喜欢/最困难/最想再试一次”的部分。

示例问题：

1. 这个项目里，你最喜欢哪一部分？
2. 哪一步你觉得有点难？
3. 你有没有和小伙伴一起完成一件事？
4. 如果下次再做，你想试试什么？
5. 你愿意把这个项目推荐给别的小朋友吗？为什么？

系统处理：

- MVP阶段先结构化保存问卷结果，老师和管理员可查看；
- 后续可由系统/AI自动抓取关键词，生成项目改进建议和反馈摘要；
- AI只辅助总结反馈，不替代孩子表达。

## 六、成果广场最终结构

### 6.1 页面任务

成果广场是独立展示舞台，承担：

1. 展示已审核、已授权、无隐私风险的孩子成果；
2. 给家长建立信任；
3. 给孩子留下作品被看见的舞台；
4. 鼓舞更多孩子参与；
5. 但不做排名、不做积分比较。

### 6.2 页面模块

1. 页面标题与说明；
2. 筛选区；
3. 小讲师视频成果；
4. 项目成果；
5. 孩子身份卡片弹窗；
6. 平台级 / 项目级数据展示；
7. 成果分享入口；
8. 进入相关页面的入口。

### 6.3 成果卡片信息

每张成果卡片展示：

- 成果标题；
- 成果类型：讲解视频 / 项目成果；
- 孩子昵称；
- 当前相关主身份和星级，例如：小语｜探索家 ★★；
- 简短成果说明；
- 审核 / 授权标记；
- 查看详情按钮；
- 分享按钮 / 生成分享图入口。

### 6.4 公开数据展示

可展示鼓舞型数据：

- 已有多少个问题被解答；
- 已有多少个项目成果被展示；
- 已有多少位孩子参与过协作；
- 某个项目已有多少人参与、多少个小组完成。

边界：展示平台级、项目级、群体级数据，不展示个人排名，不写“超过了多少人”。

### 6.5 点赞鼓励与行动号召

成果广场作品下方可以增加点赞按钮，用于表达鼓励创作者。

规则：

- 点赞是“感谢/鼓励”，不是排名；
- 不设置点赞排行榜；
- 不使用“最高赞”“最火作品”等刺激性语言；
- 点赞数量可以进入创作者个人成长记录或影响力记录，但默认不做公开竞争。

行动号召贴士示例：

- “你也可以提出一个好问题，让小讲师来帮你。”
- “如果你也有不同想法，可以去认领一道题，讲出你的方法。”
- “看完这个项目，你也想和小伙伴一起试试吗？”

### 6.6 分享功能

成果详情页支持生成适合保存和转发的分享图：

- 视频讲解成果卡；
- 项目成果卡；
- 结营证书图；
- 成长护照阶段摘要图；
- 年度感谢长图。

分享图只包含已授权公开的信息：孩子昵称、头像或系统头像、作品标题、主身份星级、简短感谢或鼓励语、平台标识。

移动端支持长按保存图片；桌面端支持下载图片。

### 6.7 不展示内容

成果广场不展示：

- 具体积分；
- 排名；
- 未授权个人信息；
- 细颗粒能力徽章；
- 老师后台标签；
- 未审核内容。

## 七、个人中心最终结构

### 7.1 入口规则

个人中心是统一入口，但登录后按角色分流：

- 未登录：弹出登录 / 注册；
- 学习者账号：进入孩子个人中心；
- 老师账号：进入老师工作台；
- 管理员账号：进入管理后台。

### 7.2 学习者个人中心模块

1. 孩子资料卡；
2. 我的提问；
3. 我的讲解；
4. 我的项目；
5. 成长护照；
6. 我的积分流水；
7. 老师反馈；
8. 隐私与公开授权。

### 7.3 孩子资料卡

展示：

- 孩子昵称；
- 头像：MVP优先支持系统儿童头像选择；真实头像上传作为后续功能，需家长确认和后台审核；
- 年龄 / 年级；
- 城市，可选且需授权；
- 主身份：提问者 / 小讲师 / 探索家；
- 星级；
- 主身份点亮状态：未解锁时为灰色，达成条件后点亮；
- 简短介绍：孩子可用一句话介绍自己数学方面的擅长点，或写一句和数学有关的话。

### 7.4 主身份灰色与点亮规则

孩子的三个主身份一开始可以都显示为灰色状态：

- 提问者；
- 小讲师；
- 探索家。

当孩子完成相应有效行为后，身份被点亮：

- 提问者：提交的问题审核通过；
- 小讲师：认领并上传讲解，审核通过；
- 探索家：参与并完成项目成果提交，审核通过。

点亮后可继续通过有效行为、老师能力观察记录、项目完成情况逐步提升星级。公开页面只轻展示身份和星级，不展示具体积分。

### 7.5 成长护照

成长护照展示完整成长记录，包括：

- 三个主身份星级；
- 能力徽章；
- 提问记录；
- 讲解记录；
- 项目记录；
- 老师反馈；
- 证书记录；
- 助人记录：我帮助了多少位同学、讲解了多少个问题；
- 合作记录：我和几位伙伴合作、完成了哪些项目；
- 阶段数据总结：提问数、讲解数、项目数、合作次数、获得感谢次数。

能力徽章和详细数据默认只在成长护照内展示，不在公开页面展示。

### 7.6 成长护照分享图

成长护照支持生成阶段性长图，例如：

- “我的小讲师成长卡”；
- “我的项目探索记录”；
- “这一年，感谢你帮助了 X 位同学”；
- “这一年，你和 X 位小伙伴一起完成了 X 个项目”。

分享前需要明确授权，默认隐藏真实姓名、学校、联系方式、具体积分和后台评价标签。

### 7.7 邀请分享与影响力统计

可以设置邀请分享追踪路径，记录孩子或家庭邀请新同学加入平台的影响力。

设计目标：

- 鼓励家长和孩子自然扩散；
- 让孩子感到自己的分享影响了更多同学；
- 不制造拉人头焦虑，不做公开排行。

可统计：

- 邀请链接带来的注册人数；
- 邀请后实际参与提问/讲解/项目的人数；
- 被邀请同学完成首次有效行为的人数。

成长护照表达方式：

- “你影响了13位小同学加入数学小讲师联盟。”
- “你激发了13位小同学开始提出数学问题。”
- “你的分享让更多同学看见了数学可以这样学。”

边界：

- 不做公开邀请排行榜；
- 不鼓励刷邀请；
- 更重视被邀请者是否产生真实学习行为，而不是单纯注册数量。

## 九、老师工作台最终结构

### 9.1 入口

老师工作台不出现在普通学习者导航中。老师账号点击“个人中心”后进入老师工作台。

### 9.2 模块

1. 待审核问题；
2. 待审核讲解视频；
3. 待审核项目成果；
4. 能力观察记录；
5. 退回原因模板；
6. 审核记录；
7. 异常提醒；
8. 项目管理入口；
9. 项目组队信息；
10. 项目完成情况；
11. 重要节点提醒；
12. 公开授权审核。

### 9.3 “能力观察标签”的命名说明

老师给孩子记录的不是负面意义上的“贴标签”，而是对孩子在具体学习行为中的能力观察。对外和教师工作台中建议使用：

- 能力观察；
- 成长能力记录；
- 能力观察项；
- 老师观察记录。

这些记录只用于成长护照、证书能力展示、老师工作台和后续项目匹配，不作为公开评价或比较工具。

### 9.4 老师审核原则

免费流程中老师主要负责：

- 内容安全；
- 数学正确性；
- 表达是否基本清楚；
- 是否适合公开；
- 记录能力观察项；
- 必要时选择退回原因。

不默认提供：

- 长篇个性化点评；
- 一对一讲法指导；
- 多轮问题改写服务；
- 每个免费项目的详细人工总结。

### 9.5 审核通过后的系统通知

孩子提交的问题、讲解视频、项目成果被老师审核通过后，系统应尽量自动给孩子推送一条温暖通知。

示例：

- “你的问题已经通过审核啦，正在等待小讲师来帮助你。”
- “你的讲解已经通过审核，可以帮助更多同学啦。”
- “你们小组的项目成果已经通过审核，已经记录到成长护照里。”

实现优先级：

- MVP阶段可先做站内通知/个人中心消息；
- 如果通知系统开发成本较高，可以作为P1升级；
- 但文案和状态触发规则应先进入设计。

### 9.6 项目管理视图

老师工作台中的项目管理视图至少需要看到：

- 项目名称、当前参与人数、已组队情况；
- 每组成员、分工情况、最近一次互动时间；
- 已上传材料、当前项目阶段、是否卡住；
- 待老师点评 / 待审核 / 待结营的项目；
- 异常提醒：长时间无互动、节点逾期、成果待审核、题目认领48小时未上传。

## 十、管理员后台与权限授权

### 10.1 入口

管理员账号点击“个人中心”后进入管理后台，不在普通学习者导航中展示。

### 10.2 教师权限分配

管理员账号不仅负责给孩子/家长开通项目权限，也负责给教师分配项目管理与审核权限。

后台需要支持：

- 教师A负责项目A、项目B；
- 教师B负责项目C；
- 指定教师能看到哪些项目小组、提交内容、待审核事项；
- 指定教师是否有权审核问题、讲解视频、项目成果；
- 指定教师是否有权编辑项目任务书、发布公告、填写节点反馈；
- 管理员可随时调整教师负责范围。

MVP阶段可先做“项目-教师”绑定表，实现基础权限分配；复杂的分级权限后置。

### 10.3 MVP阶段孩子/家长项目权限授权

MVP阶段先做“管理员手动开通付费项目权限”，不优先接完整支付系统。

后台用户列表至少展示：

- 家长账号 / 手机号 / 联系方式；
- 孩子昵称 / 年级；
- 当前已开通项目；
- 可手动开通项目A / 项目B / 项目营；
- 开通时间、到期时间；
- 备注；
- 操作：开通、关闭、延期。

### 10.4 后续自动支付解锁

规模化后再接入微信支付 / 支付宝 / 订单系统，实现付款后自动解锁项目权限。

原则：MVP先保证业务闭环和运营可控，自动支付解锁作为第二阶段。

## 十一、温暖提示语与教育气质

### 11.1 建立标准

温暖提示语不是简单“夸孩子”，而是网站教育气质的一部分。文案建立以《教育的目的》的理念为基底：教育不是灌输惰性知识，而是让孩子在真实经验中产生兴趣、形成理解、学会运用，并在表达、探索和合作中感到知识是活的。

所有提示语应符合：

1. 真诚，不廉价表扬；
2. 站在儿童立场；
3. 有教育引导性；
4. 承认过程，而不只奖励结果；
5. 保护孩子的勇气；
6. 让知识变得有生命；
7. 不制造比较和焦虑。

### 11.2 文案公式

```text
看见孩子的动作 + 命名其中的学习价值 + 给出温暖的继续方向
```

示例：

> 你愿意把想不明白的地方说出来，这就是很棒的数学开始。也许你的问题，会帮另一个同学一起想明白。

### 11.3 场景示例

提问后：

- “感谢你的好问题，让我们的数学更有趣。”
- “你愿意把想不明白的地方说出来，这就是很棒的数学开始。”

小讲师上传后：

- “感谢你帮助了一个同学解惑。”
- “你把自己的思路讲出来，也让别人多了一种想法。”

项目提交后：

- “谢谢你和伙伴一起完成了一次真正的数学探索。”
- “你留下的不只是答案，还有观察、尝试和合作的过程。”

退回修改时：

- “这次还差一点点，我们一起把它改得更清楚。”
- “这不是失败，只是一次继续完善的机会。”

## 十二、阶段2保留、替换、降级与排除项

### 12.1 被保留并成为最终规则的内容

- 五个主导航：首页、你问我答、项目营、成果广场、个人中心；
- 登录/注册不作为主导航；
- 学习者账号就是孩子账号；
- 家长只辅助操作与授权；
- 主身份为提问者 / 小讲师 / 探索家，初始灰色，解锁后点亮；
- 主身份可公开轻展示，能力徽章与积分默认私密；
- 问答闭环和项目营均为P0；
- 付费核心放在进阶项目包/主题项目营；
- 成果公开必须审核，并采用价值导向分享范围选择；
- 不公开排行榜、不公开积分。

### 12.2 被替换的内容

| 原讨论内容 | 最终替换为 |
|---|---|
| 登录/注册作为导航页 | 登录弹窗/受保护操作触发 |
| 家庭账号/家庭中心作为前台主体 | 学习者账号为孩子主体，家长辅助 |
| 成长中心 | 个人中心，按角色分流 |
| 问答广场 | 你问我答 |
| 我要讲题 | 我要当小讲师 |
| 项目官/项目探索者 | 探索家 |
| 公开能力徽章 | 能力徽章放入成长护照，默认私密 |
| 付费会员制/提问付费 | 付费核心放到进阶项目包/主题项目营 |

### 12.3 被降级为后续增强的内容

- 自动支付后解锁项目；
- AI自动分析协作过程；
- AI自动生成项目后反馈摘要；
- 复杂实时通知系统；
- OCR/AI题目识别自动标注；
- 自动退款/自动扣费系统；
- AI生成成长报告；
- 真实头像上传与审核；
- 复杂在线协作文档；
- 完整年度感谢长图模板；
- 更复杂的实时群聊或视频会议能力。

### 12.4 明确排除的方向

- 不做公开排行榜；
- 不公开积分总数；
- 不使用“超过多少人”等比较刺激文案；
- 不让AI替代孩子思考、讲解、项目表达；
- 不默认给免费提问/免费讲解提供长篇人工一对一点评；
- 不把老师工作台展示给普通学习者账号。
