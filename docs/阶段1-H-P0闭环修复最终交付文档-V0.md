## 一、修复目标

本轮进入 P0 闭环修复，重点处理 Student 朵朵、Teacher 知知、管理员 Apple 试跑反馈中会直接阻断真实使用信任的闭环问题：

1. 上传入口不能是假入口：头像、老师/咨询二维码必须能上传、回显、保存。
2. 老师审核不能“点完没反应”：通过后要有即时反馈，并能在已通过归档中找到。
3. 项目协作空间不能只显示 0 位成员：需要展示成员名单、开始时间、截止时间和任务卡更新规则。
4. 数据看板不能只有数字：老师/管理员点击数字或模块后必须看到具体明细。
5. OCR 未真实接入时不做假承诺：继续保留“上传照片 + 手动补充文字”的诚实降级说明。

## 二、已完成的 P0 闭环修复

### 1. 学生头像上传闭环

已完成：

- `/api/uploads` 新增 `avatar` 上传类型；
- 上传类型规则补充头像图片限制：JPEG / PNG / WEBP，5MB；

- 上传成功后即时预览并显示“头像已更新”。

验收点：个人中心“上传头像”不再是假入口。

### 2. 老师/咨询二维码上传闭环

已确认并纳入本轮规则：

- 管理员后台“企业微信/咨询入口配置”使用真实 `type="file"` 上传；

- `consultation-qr` 限定管理员角色；

- 保存后写入咨询入口配置。

验收点：管理员 Apple 可以上传老师二维码图片，并在后台保存咨询入口配置。

### 3. 老师审核归档与状态反馈

- 老师工作台“审核问题”新增“待审核问题 / 已通过问题”切换；

- 已通过问题卡片显示“已通过”标识；
- 问题列表 API 返回题目图片与手动补充/识别文字，方便老师复核题型；

验收点：Teacher 知知点“通过”后，能立刻知道是否生效，也能回头查看已通过了哪些题和讲题视频。

### 4. 项目协作空间运营信息补齐

已完成：

## 三、继续保留的边界

### OCR 自动识别

本轮没有伪造 OCR 自动识别能力。当前策略仍是：

- 可以上传题目照片；
- 需要手动补充题目文字；
- 页面明确说明 OCR 自动识别是下一批接入能力。

原因：没有真实 OCR 服务时，不能把“上传照片”包装成“自动识别”。后续若要进入 OCR P0，需要单独接入识别服务、识别中状态、失败兜底和人工修改入口。
