## 一、总体判断

这批反馈不是单纯 UI 美化，而是“真实用户端到端试跑”暴露出的三类问题：

1. **入口真实性问题**：头像上传、照片 OCR、老师二维码上传等入口如果不可用，必须真实接入，或明确降级说明，不能让用户误以为已经闭环。
2. **状态反馈问题**：老师点“通过”、管理员点数据框、用户提交申请后，系统必须给出可见状态、列表归档或详情展开，否则用户无法确认操作是否生效。
3. **信息密度与运营可解释问题**：个人中心、项目营、数据看板需要减少重复说明，并展示开始/截止时间、成员、任务更新规则等真实运营信息。

## 四、建议下一批 Stage1-H 修复顺序

### P0-1｜头像与二维码上传真实闭环核查

目标：所有“上传”入口要么真实写库并回显，要么降级为非上传入口。  
重点：头像上传、咨询/老师二维码上传、生产 `UPLOAD_DIR` 权限、public URL 可访问性。

### P0-2｜老师审核状态反馈与已通过归档

目标：老师点“通过/退回”后，卡片即时变状态；并提供已通过问题、已通过讲题视频、已通过项目成果列表。  
验收：老师能回答“我刚刚通过了什么？现在它在哪里？”

### P0-3｜项目协作空间成员与时间字段

目标：协作空间显示项目开始时间、截止时间、Day N 规则、成员列表；0 位成员必须解释为空状态，不能误导。  
验收：朵朵进入协作空间能看见自己所在小组、成员、任务节奏。

### P0-4｜后台/老师数据看板可钻取

目标：老师与管理员数据点可点击，进入对应明细列表或展开面板。  
验收：问题数、待审核数、项目报名数、成果数、成员数均能点开看到具体记录。

### P0-5｜OCR 接入决策

两种选择：

- **方案 A：真实接入 OCR**：上传题目照片后调用 OCR，自动填入识别文字，用户可修改。
- **方案 B：暂不做 OCR**：文案彻底改成“上传题目照片 + 手动补充文字”，不再出现“识别”期待。

当前代码已先按方案 B 做诚实降级，避免继续假承诺。
