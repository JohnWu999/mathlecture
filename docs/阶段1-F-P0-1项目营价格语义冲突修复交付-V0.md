# 阶段1-F｜P0-1 项目营价格语义冲突修复交付 V0

## 1. 本轮目标

修复第一轮入口真实性审计发现的 P0-1 问题：公开 `/api/projects` 中存在 `projectType: "PAID"` 但 `price: 0` 的语义冲突。

阶段1-F 验收口径不是“页面看起来像项目营”，而是公开入口必须让第一批试运营用户看到真实、诚实、一致的业务状态：

- 付费闭环未开放时，不在公开项目营里展示“付费项目 + 0 元”的矛盾状态；
- 公开项目列表和项目详情 API 的项目类型/价格语义必须一致；
- 项目详情页仍可匿名读取项目介绍，但报名/提交意向仍需登录；
- 页面文案必须说明当前是试运营/免费体验/人工确认，而不是暗示已经有在线付款闭环。

## 2. 根因

第一轮审计看到线上示例项目为：

- `projectType: "PAID"`
- `price: 0`

根因不是单纯 UI 文案问题，而是公开 API 直接返回数据库原始项目字段。当前第一批试运营尚未建立前台在线付费闭环，因此“PAID + 0”会让家长误解：到底是免费、付费、还是价格未配置。

同时自检中发现 `/api/projects/:id` 被 middleware 基础保护拦截为 401。项目详情页本身是公开项目营的一部分，项目详情读取应公开；只有 `/api/projects/:id/register` 这类报名/写入动作应继续要求登录。

## 3. 修复内容

### 3.1 公开项目语义归一

修改 `lib/project-camp-ui-rules.mjs`：

- 新增 `normalizeProjectForPublicListing(project)`；
- 当 `projectType === "PAID"` 且 `price <= 0` 时，公开输出归一为：
  - `projectType: "FREE"`
  - `price: 0`
  - `publicPricingState: "FREE_TRIAL"`
  - `publicPricingNote: "第一批试运营按免费体验项目开放；付费闭环暂未开放，不在公开页面展示付费项目。"`
- 当 `projectType === "PAID"` 且 `price > 0` 时，保留为：
  - `projectType: "PAID"`
  - `publicPricingState: "GUIDED_SERVICE"`
  - 公开显示 `主题服务 ¥xx`

### 3.2 API 输出修复

修改：

- `app/api/projects/route.ts`
- `app/api/projects/[id]/route.ts`

公开项目列表和详情均返回归一后的项目语义，避免公开 API 继续暴露 `PAID + price=0`。

### 3.3 页面展示修复

修改：

- `app/projects/page.tsx`
- `app/projects/[id]/page.tsx`

项目列表页不再用临时表达式判断 `projectType === "FREE" || price === 0`，统一走 `getProjectPriceDisplay()`。

项目详情页在报名区展示 `publicPricingNote`，明确说明第一批试运营/免费体验/付费闭环暂未开放。

### 3.4 公开读取与写入边界修复

修改 `lib/api-guard.ts`：

- `/api/projects` 公开可读；
- `/api/projects/:id` 公开可读；
- `/api/projects/:id/register` 仍保持受保护，未登录 POST 返回 401。

这保证项目营“能看清楚”，但报名/提交意向仍有真实身份边界。

## 4. 新增测试

新增：`tests/stage1f-project-pricing-authenticity-rules.test.mjs`

覆盖：

1. `PAID + price=0` 公开归一为 `FREE_TRIAL`；
2. `PAID + price>0` 保持主题服务；
3. 项目列表和详情 API 均调用归一函数；
4. 项目列表/详情页使用统一价格展示规则；
5. 项目详情读取 API 公开，报名写入 API 仍受保护。
