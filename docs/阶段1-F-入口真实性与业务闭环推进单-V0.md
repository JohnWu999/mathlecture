# 阶段1-F｜入口真实性与业务闭环推进单 V0

生成时间：2026-06-09 05:22 CST

## 一、进入判断

阶段0视觉收口已完成；阶段1第一轮 P0 真实闭环补齐已部署并记录。现在进入阶段1-F，重点不再做视觉修饰，而是继续处理真实试运营前最容易暴露的问题：页面入口是否真实、按钮是否写入状态、未完成能力是否被诚实降级。

## 二、本阶段目标

一句话目标：

> 让第一批真实用户看到的主要入口，不再出现“看起来能点、实际无法完成”的假闭环。

## 三、本阶段优先范围

### F-1：全站入口清单可视化

- 梳理首页、你问我答、提交问题、问题详情、项目营、项目详情、协作空间、成果广场、个人中心、老师工作台、管理员后台的可见按钮。
- 将每个按钮标注为：
  - 已真实闭环；
  - 半闭环，需要补动作或提示；
  - 暂不开放，需要降级文案；
  - 需要权限/登录后才能操作。

### F-2：未登录/无权限动作的真实反馈

- 关键操作必须清楚告诉用户下一步：登录、等待审核、联系老师、查看后台状态。
- 不使用粗糙 alert 作为核心闭环。
- 不让用户提交后不知道状态在哪里看。

### F-3：试运营空状态和样例数据

- 成果广场、项目营、你问我答等公开页面若数据不足，必须有可信空状态或审核中说明。
- 不用“加载中...”长期占位冒充内容。

### F-4：后台可追踪状态

- 前台提交、报名、上传、授权、撤回等动作，必须能在老师/管理员/个人中心看到对应状态。
- 后台状态命名要使用运营语义，不使用技术状态吓用户。

### F-5：假入口降级

- 当前不准备实现的能力，不在前台写成“上传/提交/开通/自动完成”。
- 如只支持链接，则明确写“粘贴链接”；如只支持人工处理，则明确写“提交意向，老师/管理员跟进”。

## 四、验收标准

1. 每个主要按钮都有真实后端动作、状态反馈或明确降级说明。
2. 受保护接口未登录返回 401，越权返回 403；页面级入口不出现重复 basePath 跳转。
3. 前台公开页不会因空数据显得像空壳。
4. 老师/管理员后台能看到前台关键提交的状态。
5. 阶段结束必须生成最终交付文档，且只保留最新结论，不机械拼接历史版本。

## 五、执行原则

- 先审计，再改代码。
- 先补真实状态，再改文案。
- 先保护权限，再开放入口。
- 不把 UI 漂亮当作业务完成。
