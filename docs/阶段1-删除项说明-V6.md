# 阶段1：删除项说明 V6

项目：数学小讲师联盟  
当前阶段：阶段1｜内容清单  
当前交付物：删除项说明  
版本：V6  
状态：已根据犟爸关于“付费业务到底在哪里”和“老师审核成本如何支付”的疑问修订

---

## 一、V6 修订依据

本版本在 V5 基础上继续修正三件事：

1. **提问不应设计成付费项目。** 提问是社区入口和学习起点，不适合让老师做“问题改进建议”的付费服务。
2. **小讲师视频不应默认提供付费个性化讲解建议。** 孩子有自己的讲法，只要数学正确、同伴能听明白，就不需要老师指定讲法。
3. **付费核心不应放在提问和小讲师视频，而应主要放在进阶项目/主题项目/项目包。** 同时需要通过审核限额、自动化、项目收入反哺审核成本，保证免费社区闭环可持续。

---

## 二、先修正两个不合适的说法

### 2.1 提问不做付费项目

提问本身不建议收费，也不建议设置“付费问题改进服务”。

原因：

1. 提问是孩子进入社区的低门槛入口；
2. 老师不能用成人标准要求孩子“换一种更好的问题”；
3. 过度改造问题会破坏孩子真实表达；
4. 如果提问都收费，会提高参与门槛，不符合社区冷启动。

### 2.2 提问中的老师职责

提问环节中，老师只做轻审核，不做深度点评。

老师审核重点：

- 是否安全；
- 是否完整；
- 是否适合公开；
- 是否重复或明显无效；
- 是否需要补充图片/题目条件。

系统反馈即可：

- 已通过；
- 需要补充图片；
- 需要补充题目条件；
- 暂不适合公开。

不做：

- “你这个问题提得不好”；
- “你应该换一个问题”；
- “老师帮你改写成一个高级问题”；
- 提问付费修改服务。

---

## 三、小讲师视频不默认提供个性化讲法建议

### 3.1 为什么不需要老师指导讲法？

小讲师视频的核心是：

> 孩子用自己的方式把题讲清楚，让别人听明白。

只要：

- 数学正确；
- 关键步骤清楚；
- 同伴能听懂；
- 内容安全；

就应该被接收。

老师不应默认要求孩子使用某种标准讲法，也不应过度纠正孩子的表达风格。

### 3.2 小讲师视频中的老师职责

老师负责：

1. 数学正确性审核；
2. 内容安全审核；
3. 表达是否基本清楚；
4. 能力标签勾选；
5. 必要时退回并选择原因。

### 3.3 小讲师视频不作为主要付费业务

不建议把“小讲师视频个性化点评”做成主要付费业务。

原因：

1. 容易变成老师纠正讲法；
2. 会削弱孩子真实表达；
3. 老师成本高，但产品价值不一定更强；
4. 与“孩子教孩子”的核心不完全一致。

---

## 四、付费业务核心应放在哪里？

建议核心付费业务放在：

> 进阶项目 / 主题项目营 / 项目包

而不是放在提问或小讲师视频上。

### 4.1 免费部分承担什么？

免费部分承担产品完整闭环和社区增长：

1. 免费提问；
2. 免费认领问题；
3. 免费上传小讲师视频；
4. 少量免费基础项目；
5. 自动化成长记录；
6. 自动化基础证书；
7. 主身份和星级成长。

免费部分的作用是：

- 让孩子参与起来；
- 让家长看到产品价值；
- 让社区有真实内容；
- 让优秀孩子进入进阶项目。

### 4.2 付费部分承担什么？

付费部分承担更完整、更有组织的学习体验：

1. 进阶项目任务书；
2. 主题项目营，例如 5 天项目、10 天项目；
3. 小组协作空间；
4. 阶段节点提醒和组织；
5. 项目过程材料；
6. 项目结营证书；
7. 个性化贡献描述；
8. 必要时老师项目反馈；
9. 家长可读的项目总结。

---

## 五、推荐商业结构：免费社区 + 付费项目包

### 5.1 不建议一开始做基础会员制

不建议把免费入口改成“一年基础会员”。

原因：

1. 会抬高参与门槛；
2. 家长还不了解价值时不容易付费；
3. 低龄孩子参与频率不稳定，年费容易产生压力；
4. 容易从“学习社区”变成“会员制课程平台”。

### 5.2 建议采用项目包收费

更适合采用：

> 免费社区 + 付费项目包

例如：

- 免费：你问我答 + 小讲师视频 + 少量基础项目；
- 付费：5 次进阶项目体验包；
- 付费：10 次项目成长包；
- 付费：主题项目营，例如“图形探索营”“测量与估算营”“数据小侦探营”。

这样既不阻断免费参与，又能形成付费业务。

## 六、付费项目会不会太单一？

不会，关键是项目要做成“主题项目体系”，而不是只有一个单品。

### 6.1 项目可以分层

| 层级 | 示例 | 付费方式 |
|---|---|---|
| 免费基础项目 | 纸桥挑战体验版、我的房间数学地图 | 免费或注册后开放 |
| 进阶项目 | 纸桥承重挑战进阶版、校园测量任务 | 单项目/项目包 |
| 主题项目营 | 图形探索营、测量估算营、数据小侦探营 | 5 天/10 天项目包 |
| 展示型项目 | 小小数学展、家庭数学博物馆 | 项目营/活动制 |
| 长期成长包 | 每月 2 个项目 + 成长记录 | 可作为后续订阅，不作为 P0 |

### 6.2 项目包比会员制更适合早期

项目包的优点：

1. 家长知道自己买的是什么；
2. 老师成本可以按项目估算；
3. 孩子完成后有成果和证书；
4. 可以不断扩展项目主题；
5. 不会把所有基础功能都变成收费门槛。

## 七、老师审核成本如何支付？

免费部分确实也有老师审核成本，因此必须设计成本控制机制。

### 7.1 成本控制原则

免费社区可以存在老师审核，但必须做到：

1. 审核轻量化；
2. 标签化；
3. 模板化；
4. 有每日/每周限额；
5. 优先自动检测明显问题；
6. 项目收入反哺基础审核。

### 7.2 免费功能限额建议

为了保护老师工作量，可以设置温和限额：

| 免费功能 | 建议限制 |
|---|---|
| 提问 | 每周可提交 1–2 个问题进入审核 |
| 小讲师视频 | 每周可提交 1 个讲解视频审核 |
| 免费基础项目 | 开放少量体验项目，例如 1–2 个 |
| 结营证书 | 免费项目生成自动证书，不含个性化老师长评 |

这些限制不叫“会员限制”，而叫：

> 为了保证每个作品都能被认真审核，每位学习者每周有固定提交机会。

### 7.3 积分也可以辅助控制成本

可以用积分作为提交机会或项目解锁辅助，例如：

- 提交问题消耗少量积分或免费额度；
- 回答/讲解被采纳获得积分；
- 积分可兑换一次额外提交机会；
- 积分可抵扣部分进阶项目体验。

但要注意：

- 不公开积分；
- 不做排行榜；
- 不让孩子为了积分刷内容。

## 八、付费产品建议

### 8.1 P0 阶段建议只做一种付费主线

P0 不建议同时做会员、课程、项目包、点评包、家长报告等太多商品。

建议只做：

> 进阶项目包

### 8.2 进阶项目包可设计为

示例：

1. **5 次项目体验包**
   - 适合初次付费家庭；
   - 包含 5 个进阶项目任务；
   - 每个项目有任务书、协作空间、成果提交、结营证书；
   - 老师提供项目审核和简短贡献描述。

2. **10 次项目成长包**
   - 适合持续参与家庭；
   - 包含 10 个主题项目；
   - 可以形成阶段性成长记录；
   - 结营证书和成长护照更完整。

3. **主题项目营**
   - 例如“图形探索营”“数据小侦探营”；
   - 以 5 天或 10 天为周期；
   - 更适合集中运营和展示成果。

### 8.3 后续可以扩展的付费形态

等产品跑通后，再考虑：

- 年度项目成长计划；
- 家庭项目包；
- 主题营合集；
- 项目展示活动；
- 深度老师反馈包。

但这些不建议 P0 一开始就做。

## 九、免费/付费边界修正版

| 模块 | 免费 | 付费 |
|---|---|---|
| 提问 | 免费提交，轻审核，系统反馈 | 不单独收费，不做问题改进服务 |
| 小讲师视频 | 免费提交，审核 + 能力标签 + 系统反馈 | 不作为主要付费点评业务 |
| 基础项目 | 少量免费体验项目，自动结营证书 | 可作为进阶项目入口 |
| 进阶项目 | 可公开介绍和成果样例 | 项目包/主题营收费 |
| 老师反馈 | 免费中只做审核、标签、模板反馈 | 项目节点反馈、贡献描述、结营证书、简短个性化建议 |
| 成长护照 | 自动记录主身份、星级、能力标签 | 付费项目可产生更丰富记录 |
| 家长总结 | 免费不默认提供 | 付费项目可提供简短项目总结 |

## 十、最终建议：完整性和可持续性的平衡

### 10.1 产品完整性靠免费闭环

免费必须能跑通：

> 提问 → 认领 → 讲解 → 审核 → 公开 → 成长记录

以及少量：

> 基础项目 → 成果提交 → 自动证书

否则用户无法理解产品价值。

### 10.2 成本支付靠付费项目包

老师审核成本不靠提问收费，也不靠小讲师点评收费，而是靠：

> 进阶项目包 / 主题项目营收入反哺基础审核成本

### 10.3 成本控制靠限额和自动化

免费社区不能无限提交。

通过：

- 每周提交额度；
- 系统模板反馈；
- 老师标签化审核；
- 自动证书；
- 自动成长记录；
- 项目包收入反哺；

来保证产品可持续。

---

## 十一、V6 结论

1. 提问不做付费项目，不做老师问题改进服务。
2. 小讲师视频不做主要付费点评业务，老师不默认指导讲法。
3. 免费社区必须保留完整参与闭环，但要设置温和提交额度和自动化反馈。
4. 付费核心建议放在进阶项目包和主题项目营。
5. 不建议 P0 一开始做基础会员制，避免提高门槛。
6. 老师审核成本通过自动化、限额和项目包收入反哺来解决。
7. P0 阶段建议先设计一种主付费线：进阶项目包。
