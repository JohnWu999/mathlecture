## 一、V1 修订依据

本版本基于分页内容清单 V0 与犟爸反馈修订，重点吸收以下决策：

1. **成果广场** 同意作为独立分页进入 V0/V1 页面结构。
2. **问答闭环和 PBL 项目营都作为 P0**，因为问答与项目都是产品核心，不应把 PBL 延后到弱优先级。
3. **个人中心 / 成长护照 与 家长进度页合并**，形成“成长中心”。原因是孩子是一、二年级，通常不能独立登录网站，应由家长帮助注册并共同使用账号查看成长记录。
4. 页面结构需要大幅收敛。导航栏只保留主要入口，不把上传问题、上传讲题、问题详情等都作为一级页面。
5. 上传问题、上传讲题、问题详情等属于 **问答广场内部功能入口或子页面**。
6. 项目营介绍、任务书、项目协作属于 **PBL 项目营内部功能入口或子页面**。
7. 老师审核页不放在公开导航栏。老师登录后应根据角色自动进入老师工作台 / 审核页，而不是并入普通登录页内容。

## 二、V1 页面结构总原则

### 1. 对外导航要少

家长第一次进入网站时，不应该看到十几个页面入口。主导航应只保留最核心的产品入口。

建议主导航为：

1. 首页
2. 问答广场
3. 项目营
4. 成果广场
5. 成长中心
6. 登录 / 注册

说明：

- “成长中心”登录后显示，未登录时可隐藏或显示为“我的成长”。
- 老师工作台不放在普通主导航中，老师身份登录后自动进入。

### 2. 功能页可以存在，但不作为主入口

以下页面/功能仍然需要，但应作为内部入口、弹窗、抽屉或子路由存在：

- 问题详情；
- 上传问题；
- 上传讲题；
- 追问/反馈；
- 项目营介绍；
- 项目任务书；
- 项目协作空间；
- 老师审核页。

它们不是导航栏里的一级页面，而是用户在具体场景中自然进入的操作页。

### 3. 以“场景入口”组织页面，而不是以“功能表单”组织页面

V1 的页面结构从 V0 的“功能页列表”改为“场景页 + 内部动作”。

- 问答相关动作统一归入问答广场；
- PBL 相关动作统一归入项目营；
- 个人记录和家长查看统一归入成长中心；
- 老师审核统一归入老师工作台。

## 四、主页面一：首页

**页面任务：**

让首次访问的家长和孩子快速理解：这是什么、适合谁、怎么参与、是否安全可信、有什么成果。

**主要信息项：**

1. 产品名称与核心主张；
2. 一句话定位；
3. 适合谁 / 不太适合谁；
4. 孩子怎么参与：免费提问、自主认领、项目合作；
5. 问答广场如何运转；
6. 安全、质量与反焦虑承诺；
7. 成果展示预览与成果广场入口。

**主要入口：**

- 我要提问 → 进入问答广场内的上传问题入口；
- 进入问答广场；
- 了解项目营；
- 进入成果广场；
- 注册 / 登录。

**不承担：**

- 不展示完整积分规则；
- 不展示完整 PBL 任务书；
- 不展示全量成果列表；
- 不做老师后台说明。

## 五、主页面二：问答广场

**页面任务：**

承载完整问答闭环，是免费提问、问题浏览、自主认领、讲解上传、反馈追问的核心场景页。

**主要信息项：**

1. 页面定位：提出真实数学问题，也可以认领问题成为小讲师；
2. 主要行动：我要提问、我要认领、查看我认领的题；
3. 问题列表：年级、知识点、难度、状态、匿名提问者、发布时间；
4. 问题状态：待审核、待认领、已认领、讲解审核中、已发布讲解、追问中、已解决、重新待认领；
5. 问答流程：提问 → 审核 → 发布 → 自主认领 → 系统锁定 → 上传讲解 → 老师审核 → 发布 → 反馈；
6. 温和规则：真实提问、清楚拍题、说出卡点、用自己的话讲解；
7. 安全提示：不上传隐私、不上传无关内容、不公开比较。

**内部入口 / 子功能：**

### 1. 上传问题

入口位置：问答广场顶部按钮“我要提问”。

功能要点：

- 免费注册后即可提交；
- 上传题目图片或输入文字；
- 选择年级/知识点；
- 写一句“我哪里不明白”；
- 提醒不要上传真实姓名、学校、电话、微信、家庭隐私；
- 提交后进入待审核；
- 审核通过后获得小积分并进入问答广场。

### 2. 问题详情

入口位置：点击任意问题卡片。

功能要点：

- 展示题目、卡点、年级、知识点、状态；
- 待认领时显示“我来讲讲”；
- 已认领时显示“已有小讲师正在准备讲解”；
- 已发布时展示讲解视频；
- 提问者可反馈“明白了 / 还有疑问 / 需要增援”。

### 3. 上传讲题

入口位置：认领成功后，从问题详情或我的任务进入。

功能要点：

- 展示已认领题目摘要；
- 提醒“讲题不是表演，用自己的话讲清楚”；
- 上传讲解视频；
- 可补充草稿纸或步骤说明；
- 提交后进入老师审核；
- 可主动释放题目。

**关键机制：**

- 认领不做老师预审核；
- 点击认领后系统自动锁定；
- 同一时间一道题只允许一个孩子认领；
- 超时未提交、主动释放或审核未通过后重新开放认领；
- 讲解视频通过老师审核后才公开。

**不承担：**

- 不展示完整 PBL 项目任务；
- 不公开积分排名；
- 不把问答做成抢答比赛。

---

## 六、主页面三：项目营

**页面任务：**

承载 PBL 项目营的介绍、报名/参与、任务书、项目协作和成果提交，是与问答广场并列的 P0 核心场景页。

**主要信息项：**

1. 项目营定位：从讲一道题进入共同完成数学项目；
2. 适合对象：愿意合作、表达、记录和动手探索的孩子；
3. 项目形式：2–3 人小组，异步为主，短同步为辅；
4. 项目周期：通常 5 天一个主题项目；
5. 能力目标：数学思维、表达、记录、合作、反思；
6. 示例项目：房间数学地图、对称图形侦探、时间小管家、纸桥承重挑战等；
7. 结果呈现：成果视频、项目报告、徽章、成果广场展示机会。

**内部入口 / 子功能：**

### 1. 项目营介绍

入口位置：项目营顶部说明区。

功能要点：

- 说明项目营是什么；
- 说明和问答广场的关系；
- 说明适合谁；
- 展示项目案例和成果样例。

### 2. 项目任务书

入口位置：项目列表或已报名项目卡片。

功能要点：

- 项目标题与故事情境；
- 数学概念与能力目标；
- 所需材料；
- Day1–Day5 任务说明；
- 小组分工；
- 成果要求；
- 提交入口。

### 3. 项目协作空间

入口位置：进入已参加项目后。

功能要点：

- 小组成员；
- 今日任务；
- 讨论记录或留言；
- 上传照片、记录表、草稿或视频；
- 老师提示；
- 项目进度；
- 最终成果提交。

**设计要求：**

- 项目必须有真实数学概念；
- 适合小学一、二年级具体操作；
- 鼓励测量、观察、分类、比较、记录、画图、解释；
- 不把 PBL 做成泛泛手工。

**不承担：**

- 不作为普通课程列表；
- 不做大而全班级管理；
- 不把项目结果变成比赛排名。

## 七、主页面四：成果广场

**页面任务：**

作为孩子的作品展览墙，展示优秀小讲师视频、项目成果和成长片段，建立家长信任，也给孩子真实舞台。

**主要信息项：**

1. 页面定位：这里不是排行榜，而是孩子的作品展览墙；
2. 成果分类：小讲师视频、项目成果、成长片段、老师精选；
3. 成果卡片：标题、年级、知识点/项目主题、匿名或昵称、徽章、简短说明；
4. 视频/作品展示：公开视频或项目成果页；
5. 老师点评：简短说明亮点，不做分数排名；
6. 筛选方式：按年级、知识点、项目主题、徽章筛选；
7. 引导入口：我也想提问 / 我也想成为小讲师 / 了解项目营。

**呈现原则：**

- 不显示公开积分；
- 不做排行榜；
- 不使用“最强”“第一名”等比较语言；
- 强调真实成长、清楚表达和项目过程。

**不承担：**

- 不替代问答广场；
- 不展示未审核视频；
- 不公开孩子隐私信息。

---

## 八、主页面五：成长中心

**页面任务：**

合并原“个人中心 / 成长护照”和“家长进度页”，作为家长和孩子共同查看的个人成长空间。

**合并原因：**

数学小讲师联盟面向小学一、二年级孩子，孩子通常不能独立注册、登录和管理账号。更合理的方式是：

> 家长帮助注册，一个孩子与父母共同使用一个账号，在成长中心里查看提问、讲解、项目、积分、徽章和老师反馈。

**主要信息项：**

1. 孩子身份与基础信息：昵称、年级、成长身份；
2. 我的任务：待提交讲解、待修改视频、项目今日任务、待反馈问题；
3. 我的提问：审核中、待认领、已解决、追问中；
4. 我的讲解：已认领、审核中、已发布、需修改；
5. 我的项目：正在参与的项目、历史项目、项目成果；
6. 积分与徽章：积分仅自己可见，徽章可公开展示；
7. 家长查看与设置：老师反馈摘要、隐私授权、公开视频授权、账号信息。

**显示规则：**

- 积分只对自己和家长可见；
- 徽章、作品可在授权后公开展示；
- 不显示和其他孩子的排名比较；
- 不出现“落后了”“超过了多少人”等焦虑提示。

**主要入口：**

- 继续完成讲解；
- 查看我的问题；
- 查看我的项目；
- 查看我的徽章；
- 家长授权设置。

**不承担：**

- 不做老师审核后台；
- 不展示其他孩子详细数据；
- 不制造连续打卡压力。

## 九、主页面六：登录 / 注册

**页面任务：**

让用户低门槛进入平台，并根据账号角色进入不同空间。

**主要信息项：**

1. 注册定位：免费注册即可提问；
2. 基础登录方式：手机号/验证码或账号密码；
3. 默认账号体系：一个孩子与父母共同使用一个家庭账号；
4. 孩子信息：昵称、年级，可后续补充；
5. 隐私提示：公开展示使用昵称，不展示真实姓名；
6. 注册后引导：我要提问、进入问答广场、了解项目营、进入成长中心；
7. 老师登录：老师使用后台分配或邀请账号登录，不允许公开注册自选老师身份。

**角色跳转规则：**

- 普通家庭账号登录后 → 进入成长中心，或回到刚才访问的问答/项目页面；
- 老师账号登录后 → 自动进入老师工作台 / 审核页；
- 管理员账号登录后 → 自动进入管理后台；
- 未登录用户点击“我要提问” → 先登录/注册，完成后返回上传问题入口。

**关键判断：老师审核页是否并入登录页？**

不建议把老师审核页“并入登录页”。更准确的设计是：

> 登录 / 注册页只负责身份验证；老师审核页是老师身份登录后的目标页面。

原因：

1. 登录页是入口，不应承载审核工作内容；
2. 老师审核页属于后台工作台，不应暴露给普通家庭用户；
3. 角色跳转可以解决入口问题：老师登录后自动进入老师审核页；
4. 这样既保持主导航简洁，也保证权限边界清楚。

**安全要求：**

- 公开注册不得允许用户自选老师或管理员身份；
- 默认角色应为家庭/学生账号；
- 老师和管理员由后台创建或邀请；
- 老师工作台必须有权限校验，不能仅靠前端隐藏。

**不承担：**

- 不做复杂能力测评；
- 不要求一开始填写大量孩子背景；
- 不把注册变成申请表。

## 十、内部后台：老师工作台 / 审核页

**页面定位：**

老师工作台不是公开主导航页面，而是老师角色登录后进入的后台页面。

**页面任务：**

帮助老师高效审核问题、讲解视频和项目成果，守住数学正确性、内容安全和基本表达清晰度。

**主要信息项：**

1. 待审核问题：安全、完整、适合、重复；
2. 待审核讲解：数学正确、表达基本清楚、视频安全；
3. 待审核项目成果：数学目标、项目过程、成果完整性、安全；
4. 审核结果按钮：通过、退回修改、不适合发布、释放题目、需要增援；
5. 温和反馈模板：给孩子和家长的修改建议；
6. 异常提醒：频繁乱提交、频繁认领释放、可疑互相采纳；
7. 审核记录：保留操作日志。

**审核边界：**

- 老师守数学正确性和安全边界；
- 不把孩子表达改成成人脚本；
- 不以“表演效果”替代“真实理解”；
- 不让未审核内容公开展示。

## 十一、P0 页面与功能优先级

犟爸已明确：问答闭环和 PBL 项目营都重要，应共同作为 P0。

### P0 主页面

1. 首页；
2. 问答广场；
3. 项目营；
4. 成果广场；
5. 成长中心；
6. 登录 / 注册；
7. 老师工作台 / 审核页。

### P0 必须跑通的核心闭环 A：问答闭环

1. 家庭账号注册 / 登录；
2. 免费提交问题；
3. 老师轻审核问题；
4. 问题进入问答广场；
5. 孩子自主认领；
6. 系统自动锁定；
7. 上传讲解视频；
8. 老师审核视频；
9. 视频发布；
10. 提问者反馈；
11. 成长中心记录提问、讲解、积分、徽章。

### P0 必须跑通的核心闭环 B：PBL 项目闭环

1. 查看项目营；
2. 进入项目任务书；
3. 加入或被分配到小组；
4. 查看每日任务；
5. 上传过程记录；
6. 提交项目成果；
7. 老师审核成果；
8. 成果进入成果广场；
9. 成长中心记录项目和徽章。

### P0 可以简化但不能缺席的部分

- 项目协作空间可以先做轻量版：任务说明 + 上传记录 + 小组信息 + 老师反馈；
- 成果广场可以先展示精选成果卡片，不必一开始做复杂筛选；
- 成长中心可以先合并显示提问、讲解、项目、徽章，不必一开始做复杂数据图表；
- 老师工作台可以先以审核队列为主，不必做完整运营分析。

```text
首页
├─ 问答广场
```

## 十三、与 V0 相比的主要变化

### 1. 页面数量从“12 个并列页面”收敛为“6 个主入口 + 1 个老师后台”

V0 中的问题详情、上传问题、上传讲题、PBL 任务书、家长进度页、老师审核页等容易被理解为并列页面。

V1 改为：

- 对外主导航只保留 6 个入口；
- 操作页归入所属场景；
- 老师后台通过角色登录进入。

### 2. 问答广场从“列表页”升级为“问答闭环场景页”

问答广场不只是展示问题列表，还承载：

- 上传问题；
- 问题详情；
- 自主认领；
- 系统锁定；
- 上传讲解；
- 反馈追问。

### 3. 项目营从“介绍页”升级为“PBL 核心场景页”

项目营不只是介绍 PBL，还承载：

- 项目介绍；
- 任务书；
- 小组协作；
- 过程记录；
- 成果提交。

### 4. 成长中心合并家庭视角和孩子成长记录

不再拆成“个人中心”和“家长进度页”。

原因：

- 孩子年龄小；
- 家长帮助注册和使用；
- 一个家庭账号共同查看更符合实际；
- 可以减少导航复杂度。

### 5. 老师审核页不并入登录页，而是登录后的角色跳转页面

登录页只做身份验证；老师审核页是老师工作台。

## 十四、分页内容清单 V1 验收自检

### 标准1：每个主页面能用一句话说清“用户看到它能理解什么”

- 首页：用户理解产品是什么、适合谁、怎么参与、是否可信。
- 问答广场：用户完成免费提问、自主认领和讲解反馈。
- 项目营：用户进入 PBL 项目任务、协作和成果提交。
- 成果广场：用户查看孩子真实讲解和项目成果。
- 成长中心：家庭共同查看孩子提问、讲解、项目、积分、徽章和反馈。
- 登录 / 注册：用户低门槛进入平台，并按角色跳转。
- 老师工作台：老师完成问题、视频和项目成果审核。

结论：通过。

### 标准2：没有两个主页面表达同一意思

结论：通过。

说明：

- 首页负责总理解；
- 问答广场负责问答闭环；
- 项目营负责 PBL 闭环；
- 成果广场负责公开作品展示；
- 成长中心负责个人/家庭记录；
- 登录 / 注册负责身份验证；
- 老师工作台负责后台审核。

### 标准3：每个主页面信息项不超过 7 个

结论：通过。每个主页面主要信息项均控制在 7 个以内。
