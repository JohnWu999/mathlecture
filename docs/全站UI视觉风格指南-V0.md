# 全站 UI 视觉风格指南 V0

项目：数学小讲师联盟  
当前阶段：阶段3补充交付｜UI视觉系统  
版本：V0  
状态：作为后续高保真 UI、前端组件开发、页面改版、封面/海报模板设计的统一依据  
依据：阶段1最终交付文档 V1、阶段2最终交付文档 V2、阶段3最终交付文档 V1

---

## 一、为什么需要单独的 UI 视觉风格指南

数学小讲师联盟不是普通内容网站，也不是刷题平台。它同时面向孩子、家长、老师和管理员，页面类型包括：首页、你问我答、项目营、成果广场、个人中心、老师工作台、管理员后台、分享海报、站内封面。

如果没有独立的 UI 视觉风格指南，后续开发容易出现：

1. 首页温暖，后台冰冷；
2. 你问我答像社区，项目营像电商；
3. 成果广场像作品平台，个人中心像管理系统；
4. 卡片、按钮、标签、弹窗、提示语风格不统一；
5. 新增页面时，每次靠开发者临时发挥；
6. 分享海报和站内封面与网站主体脱节。

因此，本指南的目标不是做“装饰”，而是为整个产品建立稳定的视觉语言和组件规范。

---

## 二、视觉定位

### 2.1 核心方向

**温暖纸面感 + 清晰数学网格 + 儿童作品展墙 + 可信赖的老师后台。**

### 2.2 气质关键词

- 温暖；
- 干净；
- 有秩序；
- 儿童友好但不幼稚；
- 家长可信；
- 低焦虑；
- 有数学感，但不冷冰冰；
- 像真实学习社区，而不是竞赛榜单。

### 2.3 不采用的视觉方向

| 不采用方向 | 原因 |
|---|---|
| 纯游戏化闯关风 | 容易把产品变成积分和刺激系统 |
| 强电商促销风 | 会弱化教育信任，放大家长焦虑 |
| 冷后台 SaaS 风 | 对孩子和家长不友好 |
| 过度卡通幼儿园风 | 一二三年级孩子会觉得幼稚，家长也不够信任 |
| 高对比霓虹科技风 | 与“真实思考、低焦虑、儿童表达”不匹配 |

## 三、品牌视觉隐喻

全站视觉可以围绕 5 个隐喻展开：

| 产品行为 | 视觉隐喻 | 对应组件 |
|---|---|---|
| 提出问题 | 任务卡 / 问题便签 | QuestionCard、问题标题、困惑标签 |
| 讲解题目 | 小讲台 / 展示舞台 | 讲解视频封面、小讲师身份、老师审核章 |
| 做项目 | 探索地图 / 小组任务板 | ProjectCard、任务卡、进度条 |
| 老师审核 | 印章 / 温暖批注 | TeacherStamp、审核侧栏、退回提示 |
| 成长记录 | 成长护照 / 作品展墙 | GrowthPassport、成果广场、分享海报 |

视觉重点：**让孩子感觉自己在真实参与，让家长感觉过程安全可信。**

## 四、色彩系统

### 4.1 主色

| 名称 | 用途 | 建议色值 |
|---|---|---|
| 暖米白 | 页面背景 | `#FFF8ED` |
| 纸张白 | 卡片背景 | `#FFFFFF` |
| 深墨蓝 | 主文字 / 标题 | `#1F2933` |
| 数学蓝 | 主按钮 / 链接 / 重点操作 | `#2563EB` |
| 探索橙 | 次级强调 / 项目营 / 温暖提醒 | `#F59E0B` |
| 成长绿 | 通过 / 完成 / 正向状态 | `#22A06B` |
| 轻柔红 | 退回 / 风险提示 | `#EF6F6C` |

### 4.2 辅助色

| 名称 | 用途 | 建议色值 |
|---|---|---|
| 网格浅蓝 | 数学网格背景线 | `#DBEAFE` |
| 便签黄 | 提问卡轻背景 | `#FEF3C7` |
| 项目浅绿 | 项目卡轻背景 | `#DCFCE7` |
| 成果浅紫 | 成果卡轻背景 | `#EDE9FE` |
| 灰蓝文字 | 次级说明 | `#64748B` |
| 浅边框 | 卡片边框 | `#E5E7EB` |

### 4.3 使用原则

1. 首页和前台页面以暖米白和纸张白为主；
2. 主按钮统一用数学蓝；
3. 项目营可以适度使用探索橙和成长绿；
4. 成果广场可以使用成果浅紫作为局部背景；
5. 老师/管理员后台可以更克制，但仍保留同一套按钮、标签、卡片规则；
6. 禁止用大面积红色制造压力；
7. 禁止用高饱和大面积彩虹色造成低龄化和混乱。

## 五、字体与排版

### 5.1 字体建议

中文优先：

```css
font-family: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

数字和代码辅助：

```css
font-family: "Inter", "Noto Sans SC", system-ui, sans-serif;
```

### 5.2 字号层级

| 层级 | 用途 | 桌面端 | 移动端 |
|---|---|---:|---:|
| H1 | 首页主标题 | 48–56px | 32–36px |
| H2 | 页面标题 | 32–40px | 26–30px |
| H3 | 区块标题 | 24–28px | 20–22px |
| H4 | 卡片标题 | 18–20px | 17–18px |
| Body | 正文 | 16px | 15–16px |
| Caption | 灰色说明 | 13–14px | 13px |
| Tag | 标签文字 | 12–13px | 12px |

### 5.3 排版原则

- 一屏内不要出现过多字号；
- 孩子操作页文字要短；
- 家长说明文字可以稍长，但必须分段；
- 后台表格文字不宜过小，至少 14px；
- 所有灰色说明必须足够可读，不能过浅。

## 六、间距、圆角与阴影

### 6.1 间距系统

采用 4px 基础单位：

| Token | 数值 | 用途 |
|---|---:|---|
| `space-1` | 4px | 图标与文字间距 |
| `space-2` | 8px | 标签之间 |
| `space-3` | 12px | 表单项内部 |
| `space-4` | 16px | 卡片内边距小 |
| `space-6` | 24px | 卡片内边距标准 |
| `space-8` | 32px | 区块间距 |
| `space-12` | 48px | 首页大区块间距 |

### 6.2 圆角

| Token | 数值 | 用途 |
|---|---:|---|
| `radius-sm` | 8px | 标签、输入框 |
| `radius-md` | 12px | 按钮、小卡片 |
| `radius-lg` | 18px | 标准内容卡片 |
| `radius-xl` | 24px | 首页大卡片、Hero 区块 |

### 6.3 阴影

| Token | 用途 | 建议 |
|---|---|---|
| `shadow-card` | 普通卡片 | 轻阴影，不浮夸 |
| `shadow-focus` | 当前操作卡片 | 蓝色轻描边 + 阴影 |
| `shadow-popover` | 弹窗 / 下拉 | 中等阴影，背景遮罩淡 |

原则：卡片像纸片轻轻浮起，不做厚重商业化投影。

## 七、核心组件规范

### 7.1 按钮

#### 主按钮

用途：我要提问、提交审核、确认认领、申请参加。

视觉：

- 背景：数学蓝；
- 文字：白色；
- 圆角：12px；
- 高度：44–48px；
- 移动端触摸区域不小于 44px。

#### 次按钮

用途：看看孩子怎么学、返回、稍后再说。

视觉：

- 背景：白色或透明；
- 边框：浅边框；
- 文字：深墨蓝；
- hover 时轻蓝背景。

#### 温和提醒按钮

用途：请假退出、退回修改确认。

视觉：

- 不使用强烈红色实心；
- 使用浅红背景 + 深红文字；
- 文案要温和。

### 7.2 标签

常用标签类型：

- 年级标签；
- 知识点标签；
- 分享范围标签；
- 审核状态标签；
- 身份星级标签；
- 项目状态标签。

规则：

- 标签最多 2–4 个一组；
- 不把卡片塞满标签；
- 能力观察标签默认不在公开成果卡中展示；
- 公开标签只展示帮助理解的信息，不展示后台评价。

### 7.3 卡片

#### QuestionCard 问题卡

必须包含：

- 问题标题；
- 原题缩略图；
- 年级 / 知识点；
- 困惑类型；
- 热度说明；
- 查看详情 / 我也有困惑 / 我来讲。

视觉建议：便签感、轻边框、局部网格背景。

#### ProjectCard 项目卡

必须包含：

- 项目名称；
- 适合年级；
- 核心知识点；
- 所需人数；
- 组队状态；
- 有效时长；
- 参与条件；
- 查看介绍 / 申请参加。

视觉建议：任务地图卡，顶部可有小图标或封面色块。

#### OutcomeCard 成果卡

必须包含：

- 类型化封面；
- 成果标题；
- 小讲师 / 小组昵称；
- 身份星级轻展示；
- 点赞鼓励；
- 分享按钮。

视觉建议：作品展墙感，避免像短视频平台。

#### GrowthPassport 成长护照

必须包含：

- 三身份点亮状态；
- 我的提问；
- 我的讲解；
- 我的项目；
- 证书；
- 私密积分流水；
- 分享范围管理。

视觉建议：护照页、印章、成长记录册。

## 八、页面级视觉规则

### 8.1 首页

首页要有温暖第一印象。

规则：

- Hero 区域留白充足；
- 标签少而清楚；
- 首屏只放两个 CTA；
- 能力星云先做静态词云或轻动效；
- 公开数据使用温暖表达，不像 KPI 看板。

### 8.2 你问我答

规则：

- 问题卡清楚展示“哪里不懂”；
- 热度按钮旁有说明；
- 推荐讲解独立区域，但不压过提问；
- 页面不能像题库刷题页。

### 8.3 项目营

规则：

- 项目卡像任务邀请，而不是课程商品；
- 免费与付费对比要清楚，但不贬低免费项目；
- 所需人数和组队状态要醒目；
- 退出与延期规则入口不能隐藏。

### 8.4 协作空间

规则：

- 任务卡优先；
- 留言流辅助；
- 进度条清晰但不制造催促；
- 老师提醒要像温暖批注，不像系统警告。

### 8.5 成果广场

规则：

- 像儿童作品展墙；
- 卡片节奏舒展；
- 点赞是鼓励，不像排名；
- 分享按钮清楚但不诱导刷屏；
- 不出现“最火”“最高赞”。

### 8.6 个人中心

规则：

- 像成长护照；
- 重点是孩子的过程和作品；
- 私密积分流水不放在最显眼位置；
- 我的影响力用温暖表达，不像拉新榜。

### 8.7 老师工作台

规则：

- 比前台更高信息密度；
- 但继续使用同一色彩、卡片、标签系统；
- 审核状态清楚；
- 退回原因模板温和；
- 能力观察标签少而明确。

### 8.8 管理员后台

规则：

- 管理动作明确；
- 权限、导出、下载等高风险动作有二次确认；
- 数据表格清楚，但不脱离全站风格；
- 导出按钮不与普通查看按钮混淆。

## 九、状态与反馈

### 9.1 成功状态

示例：

- “你的问题已经提交，老师会先帮你检查。”
- “你的讲解已经上传，正在等待审核。”
- “你们小组已经开组，可以进入协作空间啦。”

视觉：成长绿 + 温暖文案。

### 9.2 退回状态

示例：

- “这次还差一点点，我们一起把它改得更清楚。”
- “题目图片有些模糊，可以重新拍一张完整的题目。”

视觉：浅红背景，不使用刺眼警告风。

### 9.3 空状态

示例：

- “这里还没有问题。也许你的第一个问题，会让大家一起开始思考。”
- “你还没有认领讲解。可以先看看有哪些问题正在等待小讲师。”
- “你的小组还在等待伙伴，满3人后会自动开启协作空间。”

空状态要引导下一步，而不是冷冰冰写“暂无数据”。

## 十、封面与分享海报规则

### 10.1 小讲师视频封面

必须包含：

- 数学小讲师联盟 Logo；
- “我来讲这道题”；
- 题目标题；
- 知识点；
- 小讲师昵称；
- “会思考，爱数学”。

### 10.2 项目成果封面

必须包含：

- 数学小讲师联盟 Logo；
- “我们完成了一个数学小项目”；
- 项目标题；
- 小组人数；
- 知识点或能力收获；
- “会思考，爱数学”。

### 10.3 分享海报

MVP 至少保留四类模板：

1. 我讲清了一道题；
2. 我们完成了一个项目；
3. 我提出了一个好问题；
4. 我的成长护照小结。

规则：

- 不展示真实姓名、学校、联系方式；
- 不展示积分总数；
- 不展示后台评价标签；
- 二维码指向公开成果或邀请链接；
- 分享文案强调启发和参与，不强调超过别人。

## 十一、响应式规则

| 设备 | 导航 | 布局 | 重点 |
|---|---|---|---|
| 手机 | Logo + 折叠菜单 | 单列卡片流 | 提问、浏览、通知、分享 |
| 平板 | 顶部导航或宽折叠菜单 | 2列为主 | 项目任务、成果查看、协作 |
| 电脑 | 完整顶部导航 | 2–3列、后台表格 | 老师审核、管理员管理、完整协作 |

移动端规则：

- 按钮不小于 44px；
- 表单字段少而清楚；
- 复杂说明折叠；
- 个人中心消息红点明显；
- 管理后台可优先保证平板/电脑，手机端只保证基础查看。

## 十二、前端实现建议

### 12.1 Design Tokens

建议在前端建立统一 tokens：

```ts
export const colors = {
  bgWarm: "#FFF8ED",
  card: "#FFFFFF",
  textMain: "#1F2933",
  textMuted: "#64748B",
  mathBlue: "#2563EB",
  exploreOrange: "#F59E0B",
  growthGreen: "#22A06B",
  softRed: "#EF6F6C",
  border: "#E5E7EB",
};
```

### 12.2 组件优先级

第一批应先做这些通用组件：

- `PageHeader`；
- `HandCard` / `BaseCard`；
- `PrimaryButton`；
- `SecondaryButton`；
- `StatusBadge`；
- `TopicBadge`；
- `TeacherStamp`；
- `QuestionCard`；
- `ProjectCard`；
- `OutcomeCard`；
- `GrowthPassportCard`；
- `EmptyState`；
- `Toast`；
- `ConfirmModal`。

原则：先做组件系统，再铺页面，避免每页单独写样式。

## 十三、视觉验收清单

后续每个页面上线前，应检查：

- [ ] 是否使用统一主导航；
- [ ] 是否使用统一按钮、卡片、标签；
- [ ] 是否符合暖米白 / 纸张白 / 数学蓝主色系统；
- [ ] 是否没有公开排名、刺激性红色、焦虑文案；
- [ ] 是否有清楚的空状态和错误状态；
- [ ] 是否移动端可读、可点、可提交；
- [ ] 是否老师/管理员后台没有脱离全站风格；
- [ ] 是否分享海报和站内封面使用统一 Logo、口号和视觉骨架；
- [ ] 是否保护儿童隐私，不暴露真实姓名、学校、联系方式、后台标签；
- [ ] 是否体现“会思考，爱数学”的教育气质。

---

## 十四、阶段结论

本指南作为阶段3最终交付的补充文件，用于保证后续开发、迭代和新增页面时，全站视觉风格保持统一。

最终判断：**需要单独设计全站 UI 视觉风格指南，并应在代码实施前先转化为前端组件与 design tokens。**
