## 1. 用户反馈

犟爸反馈：点击【个人中心】后进入登录页面，但填写账号登录后依然出现错误页面；上一轮“登录后跳转改为完整 `/math-young-lecturer/profile`”后，手机端仍不正常。

## 2. 本轮重新定位

本轮没有继续假设“只是手机缓存”，而是重新检查真实公网响应头、线上部署产物和服务端日志。

关键证据：

- 部署前公网 `/login` 响应头为：`cache-control: s-maxage=31536000, stale-while-revalidate`
- 部署前公网 `/profile` 响应头为：`cache-control: s-maxage=31536000, stale-while-revalidate`
- 这意味着登录页和个人中心页会被作为静态 shell 长时间复用，手机浏览器/微信内置浏览器可能持续拿到旧 HTML 与旧 JS chunk，即使服务端代码已经部署了新的跳转逻辑。

因此，本轮根因不是单纯的按钮 href，也不是单纯的 `router.push('/profile')`，而是：

> 登录页 / 个人中心页作为身份敏感入口，却被静态长缓存，导致手机端可能继续执行旧登录跳转 chunk。

## 3. 代码修复

提交：`98e9cdc stage1f: prevent stale auth entry shell cache`

修改文件：

- `middleware.ts`
  - 新增 `NO_STORE_PAGE_PATHS = new Set(["/login", "/profile"])`
  - 新增 `NO_STORE_CACHE_CONTROL = "no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0"`
  - 对 `/login`、`/profile` 统一设置：
    - `Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`
    - `Pragma: no-cache`
    - `Expires: 0`
  - 将 `/profile` 加入 middleware matcher，仅用于缓存头覆盖；不把个人中心页面 shell 改成强制登录跳转。

- `tests/stage1f-auth-entry-cache-rules.test.mjs`
  - 新增规则测试，要求 `/login`、`/profile` 进入 middleware 并设置 no-store。

- `tests/stage0h-profile-mobile-nav-rules.test.mjs`
  - 更新旧规则：允许 `/profile` 进入 middleware 做缓存头覆盖，但仍要求 profile 页面 shell 本身可以打开，登录/角色判断由页面和 API 完成。
