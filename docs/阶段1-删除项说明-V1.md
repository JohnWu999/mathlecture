## 一、V1 修订依据

本版本基于删除项说明 V0 与犟爸确认反馈修订，重点吸收以下决策：

1. **确认删除“登录 / 注册”作为主导航入口**，仅保留弹窗、按钮和技术路由。
2. **老师工作台不出现在普通家庭账号导航中**；所有用户都可以点击“个人中心”，系统根据登录身份自动分流。
3. **个人中心成为统一入口**：未登录时弹出登录/注册；家庭/孩子身份进入家庭个人中心；老师身份进入老师个人中心/老师工作台；管理员进入管理后台。
4. **成果广场只展示已审核、已授权内容**。
5. **项目营正式任务书和协作空间不对未登录用户开放**；项目存在免费基础项目与收费进阶项目，需要逐步解锁。
6. **全站不做公开排行榜和公开积分**，但可以展示公开徽章、身份标签、能力徽章和项目徽章，用“点亮”表达成长，不显示具体分数。
7. 需要建立一套更好听、更符合儿童学习社区的身份体系，替代生硬的“学生/家长/普通用户”。

## 三、建议身份体系

### 3.1 不建议使用的公开身份名称

以下名称不建议作为前台公开身份：

- 学生；
- 家长；
- 普通用户；
- 体验者；
- 资深用户；
- 玩家。

原因：

1. “学生/家长”过于学校化，缺少社区感；
2. “普通用户/资深用户”过于平台化，缺少教育温度；
3. “玩家”容易让家长误解为游戏产品；
4. 产品核心不是娱乐升级，而是数学表达、互助和项目成长。

### 3.2 推荐前台身份体系

建议采用“成长身份 + 能力徽章”的方式。

#### 身份一：数学探索者

对应：刚注册、正在提问、开始参与的孩子/家庭账号。

含义：

> 我愿意提出问题，也愿意开始探索数学。

适合展示：

- 个人中心；
- 提问卡片；
- 新手引导。

#### 身份二：小小提问官

对应：持续提出真实问题、问题通过审核、能说出自己卡点的孩子。

含义：

> 我会提出好问题。

可点亮条件示例：

- 审核通过 3 个真实问题；
- 至少 1 次补充说明“我哪里不明白”；
- 无乱提交记录。

#### 身份三：小讲师

对应：认领问题并上传讲解，通过老师审核的孩子。

含义：

> 我能把一道题讲给同伴听。

可点亮条件示例：

- 至少 1 个讲解视频审核通过；
- 数学正确；
- 表达基本清楚；
- 内容安全。

#### 身份四：星级小讲师

对应：多次讲解被采纳或通过审核，在某些知识点上逐渐稳定的孩子。

含义：

> 我能持续帮助同伴理解数学。

可分为：

- 铜星小讲师；
- 银星小讲师；
- 金星小讲师。

注意：

- 可以公开显示星级徽章；
- 不公开显示具体积分；
- 不显示排名；
- 不写“超过多少人”。

#### 身份五：项目探索员

对应：参加 PBL 基础项目的孩子。

含义：

> 我开始和同伴一起完成数学项目。

可点亮条件示例：

- 参加 1 个基础项目；
- 提交过程记录；
- 完成项目成果。

#### 身份六：项目小队长

对应：在项目中承担组织、记录、表达或协作角色表现稳定的孩子。

含义：

> 我能在项目中协作、记录和表达。

可点亮条件示例：

- 完成 2 个以上项目；
- 有小组协作记录；
- 老师确认有贡献。

#### 身份七：概念小专家

对应：在某一类知识点上多次讲解清楚或完成相关项目成果的孩子。

含义：

> 我在某个数学概念上讲得比较清楚。

示例：

- 图形小专家；
- 时间小专家；
- 应用题小专家；
- 统计小专家；
- 画图解题小专家。

### 3.3 后台角色名称

后台权限仍可保留清晰的技术角色：

- FAMILY / LEARNER：家庭/学习者账号；
- TEACHER：老师账号；
- ADMIN：管理员账号。

前台展示不要直接暴露技术角色名。

## 四、徽章与等级公开规则

### 4.1 删除公开积分，但保留公开徽章

确认删除：

- 公开积分；
- 排行榜；
- 积分 Top 榜；
- “超过多少人”；
- “第一名/最强/冠军”式比较。

保留并鼓励：

- 公开身份徽章；
- 公开能力徽章；
- 公开项目徽章；
- 公开作品成果；
- 公开老师精选点评。

### 4.2 为什么徽章可以公开？

徽章公开的目的不是比较谁更厉害，而是展示成长方向。

例如：

- 金星小讲师：说明这个孩子有较稳定的讲解经验；
- 项目探索员：说明这个孩子参与过项目；
- 图形小专家：说明这个孩子在图形类问题中有经验；
- 最会画图说明徽章：说明表达方式有特点。

它展示的是能力标签，不是分数排名。

### 4.3 徽章公开边界

公开徽章必须遵守：

1. 不展示具体积分；
2. 不展示排名；
3. 不展示未授权孩子真实姓名；
4. 不展示敏感个人信息；
5. 徽章文案避免刺激比较。

### 4.4 推荐徽章类别

#### 小讲师徽章

- 铜星小讲师；
- 银星小讲师；
- 金星小讲师。

#### 提问徽章

- 小小提问官；
- 好问题发现者；
- 会追问的小朋友。

#### 项目徽章

- 项目探索员；
- 项目小队长；
- 项目记录员；
- 项目表达官。

#### 能力徽章

- 画图解题徽章；
- 逻辑表达徽章；
- 图形小专家；
- 时间小专家；
- 统计小专家；
- 应用题小专家。

#### 合作徽章

- 同伴帮助徽章；
- 认真倾听徽章；
- 补充讲解徽章；
- 增援小伙伴徽章。

## 五、项目营公开与解锁规则

### 5.1 删除“所有项目完全公开”

项目营可以公开展示，但不公开所有正式任务和协作内容。

未登录用户可以看到：

- 项目营是什么；
- 项目样例；
- 项目成果；
- 参加方式；
- 基础项目和进阶项目的区别。

登录用户可以看到：

- 可参加项目；
- 自己已解锁项目；
- 自己参与中的项目；
- 基础任务说明。

参与项目后可以看到：

- 正式任务书；
- 项目协作空间；
- 小组成员；
- 每日任务；
- 过程记录；
- 成果提交入口。

### 5.2 项目类型建议

#### 免费基础项目

定位：低门槛体验和入门训练。

适合：

- 新注册家庭；
- 第一次接触 PBL 的孩子；
- 已有一定问答参与记录但还未进入正式项目营的孩子。

可公开程度：

- 项目介绍可公开；
- 部分样例可公开；
- 正式任务书登录后可见；
- 协作空间参与后可见。

#### 进阶项目 / 收费项目

定位：更复杂、更长周期、更需要老师组织和反馈的项目。

适合：

- 已完成基础项目；
- 具备一定表达和协作基础；
- 家长愿意参加付费项目营。

可公开程度：

- 项目主题和成果样例可公开；
- 详细任务书不公开；
- 协作空间不公开；
- 参与资格、支付或兑换后解锁。

### 5.3 解锁路径建议

项目营不做“一次性全开放”，而采用逐步解锁：

1. 注册后：可查看项目营介绍和免费基础项目入口；
2. 完成第一个提问或讲解：解锁基础项目体验；
3. 完成基础项目：点亮项目探索员徽章；
4. 完成若干讲解或基础项目：解锁进阶项目申请；
5. 付费或积分兑换后：进入进阶项目任务书和协作空间；
6. 完成进阶项目：点亮更高阶项目徽章。

说明：

- 解锁机制不是为了制造焦虑，而是为了保护项目质量和孩子体验；
- 不用“你还不够格”这种语言；
- 使用“你已经准备好进入下一次探索了吗？”这类温和表达。

## 七、具体删除项说明

### 1. 删除“登录 / 注册”作为主导航分页

**最终确认：**

删除登录注册作为主导航入口，仅保留弹窗、按钮和技术路由。

**处理方式：**

- 主导航不显示“登录 / 注册”；
- 右上角可有轻量登录按钮；
- 点击受保护操作时弹出登录/注册；
- 必要时保留 `/login` `/register` 作为技术路由；
- 登录成功后回到原操作位置。

**触发登录的场景：**

- 点击个人中心；
- 我要提问；
- 我要认领；
- 上传讲解；
- 参加项目；
- 查看正式任务书；
- 进入项目协作空间；
- 提交项目成果；
- 查看个人积分和徽章；
- 老师进入工作台。

**是否影响 MVP：**

不影响。登录注册仍是 P0 能力，只是不作为主导航页面。

---

### 2. 删除普通导航中的“老师台 / 老师工作台”

**最终确认：**

老师工作台不出现在普通家庭账号导航中。

**处理方式：**

所有用户点击“个人中心”：

- 未登录：弹出登录/注册；
- 家庭账号：进入孩子与家长共同的个人中心；
- 老师账号：进入老师个人中心 / 老师工作台；
- 管理员账号：进入管理后台。

**删除原因：**

1. 老师工作台是后台能力，不是公开产品入口；
2. 普通家庭账号不应看到老师后台；
3. “个人中心”统一入口更简洁；
4. 角色分流由登录身份自动决定。

**是否影响 MVP：**

不影响。老师审核仍是 P0，只是入口从公开导航改为角色分流。

---

### 3. 删除“学生/家长/普通用户”等生硬前台身份

**处理方式：**

后台可以保留技术角色，但前台展示使用更有温度的成长身份。

**推荐前台身份：**

- 数学探索者；
- 小小提问官；
- 小讲师；
- 铜星小讲师 / 银星小讲师 / 金星小讲师；

**删除原因：**

4. 成长身份更符合“会思考，爱数学”的产品气质。

**迁移去向：**

- 后台权限仍使用技术角色；
- 前台卡片、个人中心、成果广场显示成长身份和徽章。

**是否影响 MVP：**

不影响，但需要在文案和用户模型中预留身份字段/徽章字段。

**处理方式：**

1. 老师审核通过；
2. 家庭授权公开；
3. 隐私已处理；
4. 不展示真实姓名、学校、电话等敏感信息；
5. 不展示具体积分或排名。

**迁移去向：**

- 未授权成果：只在个人中心自己可见；
- 已授权成果：可进入成果广场。

**是否影响 MVP：**

不影响，但需要在成果/视频/项目成果模型中预留授权状态。

---

### 6. 删除项目营正式任务全公开

**最终确认：**

项目营正式任务书和协作空间不对未登录用户开放；收费项目也不对免费用户公开完整内容。

**处理方式：**

项目营采用分层权限：

#### 未登录可见

- 项目营介绍；
- 项目样例；
- 公开成果；
- 基础项目/进阶项目的概念；
- 参加方式。

#### 登录后可见

- 免费基础项目入口；
- 已解锁项目；
- 可申请项目；
- 项目简要说明。

#### 解锁后可见

- 正式任务书；
- 项目协作空间；
- 每日任务；
- 小组成员；
- 过程记录；
- 成果提交。

#### 付费/兑换后可见

- 收费进阶项目完整任务；
- 进阶协作空间；
- 老师深度反馈；
- 进阶成果提交。

**是否影响 MVP：**

不影响。P0 需要跑通基础项目闭环，收费进阶项目可以预留结构，后续逐步开放。

---

### 7. 删除免费项目与收费项目无差别展示

**处理方式：**

建立项目解锁体系：

- 免费基础项目：低门槛体验；
- 进阶项目：完成基础项目或一定讲解经验后解锁申请；
- 收费项目：付费或积分兑换后进入；
- 高阶项目：完成进阶项目后开放。

**删除原因：**

1. 不同项目所需老师投入不同；
2. 项目难度不同，需要保护孩子体验；
3. 收费项目需要清晰边界；
4. 解锁路径能让成长更自然。

**迁移去向：**

- 项目营中显示“可参与 / 已解锁 / 需申请 / 需解锁”；
- 个人中心记录已解锁项目和已完成项目。

**是否影响 MVP：**

不影响。MVP 可先实现免费基础项目 + 解锁状态占位。

### 8. 删除“成长中心”作为主导航命名，统一为“个人中心”

**处理方式：**

主导航使用：

> 个人中心

内部可以保留：

> 我的成长护照

**删除原因：**

1. “个人中心”符合用户习惯；
2. 能兼容家庭账号、老师账号、管理员账号；
3. “成长中心”适合作为内部模块，不适合作为所有角色共用入口；
4. 老师点击个人中心时，应看到老师自己的工作台。

**迁移去向：**

- 家庭账号：个人中心 → 我的成长护照；
- 老师账号：个人中心 → 老师工作台；
- 管理员账号：个人中心 → 管理后台。

**是否影响 MVP：**

不影响。

### 9. 删除“家长进度页”独立页面

**处理方式：**

合并进个人中心。

家庭账号个人中心包含：

- 孩子基础信息；
- 我的提问；
- 我的讲解；
- 我的项目；
- 积分流水；
- 徽章墙；
- 老师反馈；
- 隐私授权；
- 家长设置。

**删除原因：**

1. 孩子低龄，家长与孩子共同使用账号；
2. 单独家长页会增加导航复杂度；
3. 家长查看和孩子成长记录本质是同一账号空间；
4. 可以用模块区分，而不是页面拆分。

**是否影响 MVP：**

不影响，降低复杂度。

### 10. 删除首页中的长文式说明

**处理方式：**

首页不承载长文解释，改为：

- 短句；
- 标签；
- 卡片；
- 流程图；
- 精选成果；
- 明确行动按钮。

**删除原因：**

1. 首页不是说明书；
2. 家长需要快速判断，而不是读长文；
3. 长文会弱化行动入口；
4. 视觉上会像文稿，不像产品首页。

**迁移去向：**

- 详细规则进入你问我答 / 项目营 / 个人中心；
- 理念说明可放首页卡片或后续家长说明模块，但不作为长文主内容。

**是否影响 MVP：**

不影响，提升首页转化。

### 11. 删除 SecurityGuard 的强拦截体验

**处理方式：**

建议删除或弱化，不做全站禁止复制、禁止右键、禁止选择。

**删除原因：**

1. 家长和老师可能需要复制问题文本；
2. 孩子可能需要选中文字；
3. 禁止右键不能真正保护内容；
4. 会造成可用性和无障碍问题。

**迁移去向：**

- 版权和隐私靠授权机制、审核机制、内容水印和用户协议，而不是全站禁用操作。

**是否影响 MVP：**

不影响，建议尽早处理。

### 12. 删除 alert 弹窗反馈

**处理方式：**

替换为：

- Toast；

- 审核结果反馈条。

**删除原因：**

2. 不适合孩子和老师频繁使用；
3. 无法承载温和反馈；
4. 体验显得粗糙。

**迁移去向：**

- 统一提示组件；
- 老师审核页内联反馈。

**是否影响 MVP：**

不影响，但能明显提升体验。
