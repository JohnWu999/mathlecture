## 二、最终产品原则

MVP 开发必须继续守住以下原则：

1. **孩子是真正主角**：提问、讲题、项目探索、作品沉淀都围绕孩子真实思考展开。
2. **提问、讲题、项目探索并列**：孩子可以先提问，可以后来尝试讲题，也可以通过项目慢慢学会合作。
3. **不做刷题平台**：不以题量、速度、正确率排名作为核心价值。
4. **不做公开比较系统**：不公开排行榜、不公开积分总数、不使用“最高赞”“最火”“超过多少人”等刺激性表达。
5. **积分和星级服务运转，不制造焦虑**：积分是私密成长账本和后台运营数据；星级是身份成长提示，不是排名。
6. **老师守安全与正确性，不替代孩子表达**：老师负责审核、能力观察、节点提醒和必要引导，不把孩子表达成人化。
7. **MVP 优先跑通闭环**：先完成可提交、可审核、可发布、可组队、可留言、可提醒、可回溯的数据链路；复杂 AI、自动支付、视频合成、站外通知后置。

## 三、阶段3最终采用的页面结构

### 3.1 主导航

前台主导航固定为：

```text
首页 / 你问我答 / 项目营 / 成果广场 / 个人中心
```

不进入前台主导航：

- 登录 / 注册；
- 提交问题页；
- 上传讲解页；
- 问题详情页；
- 项目任务书；
- 项目协作空间；
- 老师工作台；
- 管理员后台。

这些页面作为场景内动作、受保护子页面或角色后台存在。

### 3.2 首页最终规则

首页承担“30秒理解产品”的任务，最终采用：

- 产品名：数学小讲师联盟；
- Slogan：会思考，爱数学；
- 副标题：小学低年级孩子的数学共学社区；
- 标签：小学1–3年级 / 同伴互助 / 项目制学习 / 真实思考；
- 首屏按钮：我要提问 / 看看孩子怎么学；
- 不使用“低焦虑成长”作为首页卖点标签；
- 不使用“思维开窍”作为承诺式卖点。

适合谁最终为 3 条客观条件：

1. 校内数学基本无明显压力；
2. 对数学问题有一点好奇心；
3. 想练习表达、倾听和合作。

暂不优先适合谁最终为 3 条客观条件：

1. 当前更需要系统补基础；
2. 近期主要目标是应试提分/刷题训练；
3. 暂时不方便拍照、录制或上传作品。

### 3.3 你问我答最终规则

你问我答承担两个入口：

- **我要提问**：孩子提出真实数学问题；
- **我要当小讲师**：孩子认领一道可讲的问题，再上传讲解。

最终规则：

- 问题提交后先进入老师审核，不直接公开；
- 问题标题下必须有灰色说明：给这道题起一个方便别人看懂的名字，不是写解题过程；系统可先生成，家长只需确认或微调；
- 年级与知识点采用 1–3 年级内置标签下拉；
- “热度”文案解释为“我也有这个困惑”，不是点赞排名；
- 电脑端和手机端列表统一使用“推荐讲解”，不再出现“已发布讲解 / 推荐讲解”双标题；
- 单题详情下可以显示“已发布讲解”。

### 3.4 小讲师认领与讲解发布最终规则

- 认领后题目保留 72 小时；
- 认领弹窗必须提示：
  - 开场简单自我介绍；
  - 题目展示完整；
  - 说清楚先想什么，再做什么；
  - 如果画图或摆一摆，请让过程看得见；
- 可以请假退出，题目释放；
- 无故放弃累计 3 次，暂停新的认领机会；
- 上传讲解必须选择分享范围：
  - A：只分享给出题人和加热度同学；
  - B：愿意分享到成果广场，启发和鼓舞更多同学；
- 老师审核通过后才发布或推送。

### 3.5 项目营最终规则

项目营分为：

1. 免费基础项目；
2. 付费主题项目包；
3. 20 项长期探索计划。

项目卡必须展示：

- 项目名称；
- 适合年级；
- 核心知识点；
- 能力观察方向；
- 所需人数；
- 参与条件；
- 组队状态；
- 有效时长。

最终采用：**满 3 人自动开组并开启协作空间**。  
这里的“开组”不是“个人资格解锁”，而是小组人数达到后开启协作空间。

公开项目卡不展示“20积分”等显性积分门槛，改用“完成基础项目 / 达到基础参与条件”等低焦虑表达。积分仍可作为后台判断依据。

### 3.6 付费项目报名最终规则

付费报名采用“报名意向 + 企业微信咨询 + 后台人工跟进”模式。

报名弹窗字段：

- 孩子昵称；
- 年级；
- 我想咨询/报名的项目包；
- 可选联系方式。

最终规则：

- 不强制家长填写联系方式；
- 可选联系方式下方要说明：不强制填写，也可以直接扫码添加老师企业微信；
- 提交报名意向后，自动弹出老师企业微信二维码；
- 管理员后台记录报名意向、项目包、可选联系方式、二维码已展示状态、跟进状态；
- 付款、开通、延期、转期、保留名额、退费均由管理员 MVP 阶段手工登记。

### 3.7 项目协作空间最终规则

协作空间采用异步轻协作，不做复杂群聊和实时在线文档。

MVP 做：

- 任务卡；
- 小组留言流；
- 图片 / 视频 / 语音 + 图片 / 简短文字上传；
- 老师提醒；
- 系统状态提醒；
- 最终成果提交；
- 分享范围选择；
- 后台留痕；
- 站内消息提醒。

老师留言、小组成员 @ 我、任务状态变化、审核退回/通过，均形成站内消息。导航栏“个人中心”显示红点或数字气泡。

### 3.8 成果广场最终规则

成果广场只展示：

- 已审核；
- 已授权公开；
- 无隐私风险；
- 适合公开传播的讲解视频或项目成果。

成果广场内的作品默认可以被访客转发分享；但不进入成果广场的作品不能外传。

成果广场不展示：

- 真实姓名；
- 学校；
- 联系方式；
- 具体积分；
- 后台评价标签；
- 未授权个人信息；
- 未审核内容。

### 3.9 个人中心最终规则

个人中心是统一登录与角色分流入口：

- 未登录：进入登录 / 注册；
- 学习者：进入孩子个人中心；
- 老师：进入老师工作台；
- 管理员：进入管理员后台。

学习者个人中心包含：

- 孩子资料卡；
- 我的提问；
- 我的讲解；
- 我的项目；
- 成长护照；
- 我的消息；
- 我的影响力；
- 隐私与分享范围；
- 积分流水。

积分流水、能力观察记录、详细成长数据仅自己 / 老师 / 管理员可见，不公开。

## 五、核心数据动线自检表

### 5.1 动线 A：提问者路径

```text
登录/注册 → 我要提问 → 上传原题/填写题目文字 → 系统建议问题标题 → 家长确认或微调 → 选择年级/知识点/困惑类型 → 提交 → 老师审核 → 审核通过 → 进入你问我答列表 → 被加热度/等待讲解 → 讲解发布后收到通知 → 进入成长记录/积分流水/身份进度
```

| 检查项 | 结论 | 规则 |
|---|---|---|
| 数据对象 | ✅ 已闭合 | User、Question、QuestionHeat、Notification、PointTransaction、IdentityProgress |
| 审核节点 | ✅ 已闭合 | 问题提交后默认 PENDING，老师通过后 APPROVED |
| 展示节点 | ✅ 已闭合 | 只有审核通过问题进入列表 |
| 热度规则 | ✅ 已闭合 | 同一用户同一题只能加一次热度；热度不做排名 |
| 通知规则 | ✅ 已闭合 | 问题审核、讲解发布均生成站内通知 |
| 成长规则 | ✅ 已闭合 | 问题审核通过后点亮/推进提问者身份，写入积分流水 |

进入可认领问题 → 查看认领弹窗 → 确认认领 → 72小时倒计时 → 上传讲解 → 选择分享范围 → 老师审核 → 审核通过 → 推送给提问者和加热度同学 → 根据分享范围进入成果广场或仅相关可见 → 更新成长护照、积分流水、身份星级

|---|---|---|
| 数据对象 | ✅ 已闭合 | Question、Answer、ShareScope、ReviewResult、AnswerClarity、Notification、PointTransaction、IdentityProgress |
| 认领规则 | ✅ 已闭合 | claimedById、claimedAt、claimExpiresAt 支撑 72 小时保留 |
| 退出规则 | ✅ 已闭合 | 请假退出释放题目；无故累计 3 次暂停认领机会 |
| 审核规则 | ✅ 已闭合 | 审核结论与表达清晰度分离；数学正确、安全、基本清楚以上才推送 |

| 数据对象 | ✅ 已闭合 | Project、Group、ProjectTask、Message、ProjectSubmission、Notification、PointTransaction、IdentityProgress |
| 组队规则 | ✅ 已闭合 | requiredMembers 默认 3；WAITING 满员转 ACTIVE |
| 协作规则 | ✅ 已闭合 | 只有组员、老师、管理员可见小组内部留言与过程材料 |
| 消息规则 | ✅ 已闭合 | 老师留言、@我、任务变化、审核结果均生成站内消息 |

## 六、最终采用的数据对象清单

MVP 必须支撑以下核心对象：

| 对象 | 用途 | 关键规则 |
|---|---|---|
| User | 账号与角色 | STUDENT / TEACHER / ADMIN |
| IdentityProgress | 三身份星级 | QUESTIONER / LECTURER / EXPLORER，各自 0–3 星 |
| Question | 提问数据 | 审核通过后展示，可被加热度和认领 |
| QuestionHeat | 我也有困惑 | 同用户同题唯一，不做排名 |
| Answer | 讲解视频 | 分享范围、审核结论、表达清晰度、能力观察标签 |
| Project | 项目 | 类型、年级、知识点、所需人数、有效期、参与条件 |
| Group | 项目小组 | WAITING / ACTIVE / SUBMITTED / COMPLETED / EXPIRED |
| ProjectTask | 项目任务卡 | 支撑协作空间任务推进 |
| ProjectSubmission | 项目成果 | 审核通过后进入成长记录或成果广场 |
| Message | 小组留言 | 组员、老师、管理员可见，触发站内通知 |
| Notification | 站内通知 | 审核、留言、开组、任务变化、讲解发布 |
| ProjectInquiry | 报名意向 | 联系方式可选，跟进状态可管理 |
| PaymentRecord | 付费/退费记录 | MVP 手工登记，支持延期、转期、保留名额 |
| SiteSetting | 站点设置 | 老师企业微信二维码与咨询文案 |
| PointTransaction | 积分流水 | 每笔有原因、来源对象、可回溯 |
| Share / Poster 数据 | 分享追踪 | 成果链接、邀请码、二维码，不做邀请榜 |

## 七、审核、标签与发布规则

### 7.1 审核结论与能力标签分离

最终采用两层逻辑：

#### 第一层：审核结论

决定是否发布、推送、进入公开区域。

- APPROVED：通过；
- NEED_REVISION / REJECTED：退回修改或不通过。

#### 第二层：表达清晰度与能力观察

用于成长护照、老师后台筛选、成果广场推荐，不直接等同发布状态。

表达清晰度：

- CLEAR：清楚；
- BASICALLY_CLEAR：基本清楚；
- NEEDS_SUPPORT：需补充。

能力观察标签：

- 逻辑清晰；
- 会画图；
- 表达完整；
- 基本清楚；
- 愿意尝试表达；
- 能联系题意。

### 7.2 推送与公开规则

| 内容 | 推送给相关同学 | 进入成果广场 |
|---|---|---|
| 数学正确、安全、清楚 | 可以 | 若选择公开，可进入 |
| 数学正确、安全、基本清楚 | 可以 | 老师判断有亮点时可进入 |
| 需补充 | 不推送 | 不公开，退回修改 |

## 八、身份星级与积分运转规则

### 8.1 身份星级

| 身份 | 1星/点亮 | 2星 | 3星 |
|---|---|---|---|
| 提问者 | 1个审核通过的真实问题 | 5个有效问题 | 10个有效问题，且至少3个被解答或加热 |
| 小讲师 | 1个审核通过讲解 | 3个审核通过讲解 | 6个审核通过讲解，且至少2次获得能力观察标签 |
| 探索家 | 完成1个项目关键任务/基础项目 | 完成3个关键任务或1个完整项目 | 完成5个关键任务或2个完整项目，且有成果记录 |

### 8.2 积分规则

| 行为 | 积分 | 是否影响身份星级 |
|---|---:|---|
| 问题审核通过 | +2 | 影响提问者有效行为 |
| 讲解审核通过，基本清楚及以上 | +5 | 影响小讲师有效行为 |
| 讲解获得质量标签 | +1/标签，上限+3 | 影响小讲师质量行为 |
| 完成项目关键任务 | +2 | 影响探索家有效行为 |
| 项目成果审核通过 | +6 | 影响探索家有效行为 |
| 完成完整项目 | +10 | 影响探索家星级 |
| 手动调整 | 管理员设置 | 不自动影响星级 |
| 无故退出/违规 | 可扣分或记录异常 | 可暂停体验资格 |

积分原则：

- 积分不是公开比较工具；
- 积分不直接兑换身份星级；
- 每笔积分必须有 reasonCode、sourceType、sourceId；
- 积分可回溯、可人工修正；
- 不因刷邀请、刷点击、重复加热度获得积分。

## 九、权限与安全边界

### 9.1 页面权限

| 页面 | 访客 | 学习者 | 老师 | 管理员 |
|---|---|---|---|---|
| 首页 | 可见 | 可见 | 可见 | 可见 |
| 你问我答列表 | 可浏览公开内容 | 可提问/加热/认领 | 可浏览 | 可管理 |
| 提交问题 | 登录后可用 | 可用 | 可辅助测试 | 可管理 |
| 项目营 | 可浏览介绍 | 可报名/参与 | 可查看负责项目 | 可管理 |
| 协作空间 | 不可见 | 仅本人小组可见 | 负责项目可见 | 可见 |
| 成果广场 | 可见公开成果 | 可见公开成果 | 可见 | 可管理 |
| 个人中心 | 登录入口 | 学习者中心 | 分流到老师工作台 | 分流到管理员后台 |
| 老师工作台 | 不可见 | 不可见 | 可见 | 可见 |
| 管理员后台 | 不可见 | 不可见 | 不可见 | 可见 |

### 9.2 API 权限

必须实现：

- 未登录调用受保护 API 返回 401；
- 权限不足返回 403；
- 学习者只能管理自己的问题、讲解、项目参与、消息；
- 老师只能处理被授权的审核和项目；
- 管理员处理用户、项目权限、教师权限、报名、付费/退费；
- 任何后台 API 不能只依赖前端隐藏按钮保护。
